# 二期迭代与批次任务设计

> **用途**：作为二期研发排期、批次签收、接口联调和验收追踪的统一设计基线。  
> **范围**：只做设计输出，不包含代码实现。  
> **状态口径**：以 [项目进展总览.md](./项目进展总览.md) 为唯一状态看板；本文维护任务拆分、接口契约和验收口径。

## 1. 二期目标

在一期闭环基础上，形成“双重预防可管控、巡检可执行、人员可定位、视频可联动、交叉作业可识别、监管可对接”的扩展能力，支撑试点区域二期上线。

## 3. 全局接口约定

二期沿用一期约定，见 [01_一期落地设计/00_开发总览/一期迭代与批次任务设计.md](../../01_一期落地设计/00_开发总览/一期迭代与批次任务设计.md) 第 3 节。

新增约定：

| 项 | 约定 |
| --- | --- |
| 事件接入 | 定位/视频/门禁等外部事件接入必须支持幂等键（source + externalId + eventTime）。 |
| 规则扩展 | SIMOPS、隐患逾期、定位告警等规则统一走配置规则服务，返回结构与一期一致。 |
| 监管上报 | 报文日志只存摘要和哈希，密钥走 Jasypt/环境变量。 |
| 时序数据 | 定位轨迹高频数据与业务库分离，API 只暴露聚合查询。 |

## 10. 二期 UAT 检查清单（摘要）

| 域 | 检查项 |
| --- | --- |
| 双重预防 | 风险清单覆盖试点区域；隐患闭环率可统计 |
| 巡检 | 计划任务执行率 ≥ 项目约定值；漏检可追踪 |
| 定位 | 越界/超员事件可报警闭环；区域人数可查 |
| 视频 | AI 事件进入报警中心；作业监护留痕 |
| SIMOPS | 冲突作业可识别并阻断或协调 |
| 监管 | 约定数据域上报成功并有回执 |

# 双重预防与隐患治理落地设计

## 1. 模块目标

建立符合国内双重预防机制要求的**风险分级管控**和**隐患排查治理**能力，与一期区域、重大危险源、作业票、报警和承包商模块联动，形成“辨识—管控—检查—隐患—整改—复查—销项”闭环。

## 2. 功能范围

| 子模块 | 二期范围 |
| --- | --- |
| 风险单元 | 按区域/装置/设备划分风险单元，绑定责任部门和责任人 |
| 风险事件 | 风险描述、致险因素、可能后果、固有风险等级 |
| 管控措施 | 工程、管理、应急、培训等措施，责任岗位和检查周期 |
| 风险清单 | 单元—事件—措施树形清单，支持四色图和导出 |
| 隐患上报 | Web/移动端上报，拍照、定位、关联风险单元或巡检项 |
| 隐患治理 | 分级、派单、整改、复查、销项、逾期升级 |
| 统计分析 | 隐患逾期率、重复隐患、按区域/类型/承包商分布 |

## 3. 关键流程

### 3.1 风险清单维护

```text
划分风险单元
 -> 识别风险事件
 -> 评估固有风险等级
 -> 制定管控措施和责任岗位
 -> 发布风险清单
 -> 变更时版本留痕和审计
```

### 3.2 隐患闭环

```text
隐患发现（巡检/上报/报警转隐患）
 -> 分级和派单
 -> 责任部门整改
 -> 上传整改证据
 -> 安全部门复查
 -> 销项或退回重改
 -> 逾期自动升级通知
```

## 4. 状态机

### 4.1 隐患状态

```text
待确认 -> 整改中 -> 待复查 -> 已销项
待确认/整改中 -> 已退回
任意非销项 -> 已逾期（并行标记）
```

## 5. 数据设计

| 表 | 说明 |
| --- | --- |
| `dp_risk_unit` | 风险单元 |
| `dp_risk_event` | 风险事件 |
| `dp_control_measure` | 管控措施 |
| `dp_risk_assessment` | 风险评估记录 |
| `dp_hazard_report` | 隐患主表 |
| `dp_hazard_action` | 派单、整改、复查记录 |
| `dp_hazard_attachment` | 隐患附件 |
| `dp_hazard_escalation` | 逾期升级记录 |

## 6. 关键字段

### 6.1 风险单元 `dp_risk_unit`

| 字段 | 说明 |
| --- | --- |
| unit_code | 单元编码 |
| unit_name | 单元名称 |
| area_id | 所属区域 |
| equipment_id | 关联设备（可选） |
| major_hazard_id | 关联重大危险源（可选） |
| inherent_risk_level | 固有风险等级 |
| residual_risk_level | 残余风险等级 |
| owner_org_id | 责任部门 |
| owner_user_id | 责任人 |
| status | 草稿、生效、停用 |

### 6.2 隐患 `dp_hazard_report`

| 字段 | 说明 |
| --- | --- |
| hazard_no | 隐患编号 |
| hazard_level | 一般、较大、重大 |
| source_type | 巡检、上报、报警、作业、检查 |
| source_biz_id | 来源业务 ID |
| risk_unit_id | 关联风险单元 |
| description | 隐患描述 |
| found_at | 发现时间 |
| rectification_deadline | 整改期限 |
| status | 待确认、整改中、待复查、已销项、已退回 |
| overdue_flag | 是否逾期 |

## 7. 联动规则

| 场景 | 规则 |
| --- | --- |
| 重大危险源 | 危险源区域隐患逾期提高管理风险评分 |
| 作业票 | 区域存在未销项重大隐患时，高风险作业规则可阻断或升级 |
| 报警 | 重复报警可一键转隐患 |
| 巡检 | 巡检异常项可自动生成隐患草稿 |
| 承包商 | 承包商责任隐患纳入绩效统计 |

## 8. 接口设计

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/risk-units` | GET/POST | 风险单元查询和新增 |
| `/risk-units/{id}/events` | GET/POST | 风险事件维护 |
| `/risk-events/{id}/measures` | GET/POST | 管控措施维护 |
| `/risk-units/tree` | GET | 风险清单树 |
| `/hazards` | GET/POST | 隐患列表和上报 |
| `/hazards/{id}/confirm` | POST | 确认分级派单 |
| `/hazards/{id}/rectify` | POST | 提交整改 |
| `/hazards/{id}/review` | POST | 复查销项 |
| `/hazards/{id}/escalate` | POST | 手动升级 |
| `/hazards/overdue-check` | POST | 逾期隐患查询（供规则引擎） |
| `/hazards/statistics` | GET | 隐患统计 |

## 9. 页面设计

| 页面 | 关键能力 |
| --- | --- |
| 风险清单 | 单元树、四色图、措施和责任查看 |
| 风险单元详情 | 事件、措施、关联危险源和隐患 |
| 隐患台账 | 分级、状态、区域、逾期筛选 |
| 隐患详情 | 整改记录、复查、附件、来源追溯 |
| 移动端隐患上报 | 拍照、定位、选区域/单元、快速提交 |

## 10. 验收标准

- 风险单元、事件、措施可按区域/装置维护并形成清单。
- 隐患可完成上报、派单、整改、复查、销项全流程。
- 逾期隐患可自动标记并触发通知升级。
- 巡检异常和报警可转隐患并保留来源关联。
- 区域未销项重大隐患可被作业票规则接口查询。
- 关键操作可审计追溯。

# 人员定位与封闭化落地设计

## 1. 模块目标

接入人员定位、电子围栏、门禁和车辆系统，实现**人员在岗在位、区域越界、超员监测和进出封闭化管理**，并与作业票、承包商、报警和重大危险源联动。

## 2. 功能范围

| 子模块 | 二期范围 |
| --- | --- |
| 标签管理 | 定位标签、门禁卡、人员/承包商绑定与解绑 |
| 实时定位 | 实时位置、在线状态、区域归属 |
| 历史轨迹 | 按人员、时间、区域查询轨迹 |
| 电子围栏 | 禁入、滞留、超员区域配置 |
| 定位告警 | 越界、静止、跌倒、超员、失联、SOS |
| 门禁接入 | 进出记录、权限校验、与准入状态联动 |
| 车辆接入 | 车辆进出、预约、与区域和作业联动 |
| 封闭化视图 | 厂区人员/车辆分布、区域人数统计 |

## 3. 关键流程

### 3.1 标签绑定

```text
人员/承包商入厂准入通过
 -> 分配定位标签或门禁卡
 -> 绑定人员档案
 -> 同步至定位/门禁厂商
 -> 授权可进入区域
 -> 离场解绑
```

### 3.2 定位告警闭环

```text
定位/围栏事件接入
 -> 标准化（人员、区域、事件类型）
 -> 去重和分级
 -> 推送报警中心
 -> 值班确认和处置
 -> 关联作业票和视频监控（可选）
 -> 关闭和复盘
```

## 4. 事件类型

| 类型 | 说明 |
| --- | --- |
| AREA_ENTER | 进入区域 |
| AREA_EXIT | 离开区域 |
| FORBIDDEN_ENTER | 闯入禁入区 |
| OVERSTAY | 滞留超时 |
| OVERCAPACITY | 区域超员 |
| STATIC_TIMEOUT | 长时间静止 |
| SOS | 紧急求救 |
| OFFLINE | 标签离线/失联 |
| FALL | 跌倒（若厂商支持） |

## 5. 数据设计

| 表 | 说明 |
| --- | --- |
| `loc_tag` | 定位标签 |
| `loc_tag_binding` | 标签与人员绑定记录 |
| `loc_realtime` | 实时位置快照 |
| `loc_track_point` | 历史轨迹点 |
| `loc_geofence` | 电子围栏 |
| `loc_geofence_rule` | 围栏规则（禁入/超员/滞留） |
| `loc_event` | 定位事件 |
| `gate_access_record` | 门禁进出记录 |
| `vehicle_access_record` | 车辆进出记录 |

## 6. 关键字段

### 6.1 标签绑定 `loc_tag_binding`

| 字段 | 说明 |
| --- | --- |
| tag_no | 标签编号 |
| person_type | 内部用户、承包商人员 |
| person_id | 人员 ID |
| contractor_id | 承包商 ID（可选） |
| bind_at | 绑定时间 |
| unbind_at | 解绑时间 |
| status | 生效、已解绑 |

### 6.2 定位事件 `loc_event`

| 字段 | 说明 |
| --- | --- |
| event_type | 事件类型 |
| tag_no | 标签 |
| person_id | 人员 |
| area_id | 区域 |
| fence_id | 围栏（可选） |
| event_time | 事件时间 |
| alarm_id | 关联报警（若已转报警） |
| work_permit_id | 关联作业票（可选） |

## 7. 联动规则

| 场景 | 规则 |
| --- | --- |
| 作业票 | 作业区域人员签到可与定位到场校验交叉验证 |
| 承包商 | 未准入或黑名单人员标签不得绑定 |
| 门禁 | 证书/培训过期自动撤销门禁权限 |
| 报警 | 越界、超员、SOS 进入报警中心 |
| 重大危险源 | 危险源区域超员/禁入触发高等级告警 |

## 8. 接口设计

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/tags` | GET/POST | 标签台账 |
| `/tags/{tagNo}/bind` | POST | 绑定人员 |
| `/tags/{tagNo}/unbind` | POST | 解绑 |
| `/locations/realtime` | GET | 实时位置查询 |
| `/locations/tracks` | GET | 历史轨迹 |
| `/geofences` | GET/POST | 围栏维护 |
| `/events/ingest` | POST | 定位事件接入 |
| `/events` | GET | 事件列表 |
| `/gate/records` | GET | 门禁记录 |
| `/gate/records/ingest` | POST | 门禁记录接入 |
| `/vehicles/records/ingest` | POST | 车辆记录接入 |
| `/areas/{id}/headcount` | GET | 区域当前人数 |

## 9. 集成要求

- 支持至少一种主流定位厂商 API/消息接入，点位映射到 `base_area`。
- 门禁/车辆接入采用适配层，统一转换为平台事件模型。
- 实时位置高频数据使用时序库或缓存，业务库保留快照和关键事件。
- 敏感轨迹查询需数据权限和审计。

## 10. 验收标准

- 人员标签可与内部用户和承包商人员绑定/解绑。
- 实时位置和历史轨迹可按人员、区域查询。
- 禁入、超员、SOS 等事件可进入报警中心。
- 门禁进出记录可查询，并与准入状态联动。
- 作业票区域可查询当前在场人员数量。
- 定位相关查询和配置变更可审计。

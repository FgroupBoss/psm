# 08 需求分析与 PRD 落地设计

## 1. 文档目标

本文档基于前序市场调研、合规基线、产品蓝图、模块设计和技术架构，给出一套可直接用于研发立项、产品设计、原型评审、开发拆分、测试验收和上线运营的需求分析方法。

适用对象：

- 产品经理：输出 PRD、原型、需求池、版本规划。
- 业务顾问/HSE 专家：确认业务规则、票证模板、合规口径。
- 架构师/研发负责人：拆分服务、接口、数据模型和迭代范围。
- 测试负责人：制定测试用例、验收标准和回归范围。
- 实施团队：组织现场调研、配置、培训、上线切换。

## 2. 需求分析总流程

```text
市场与合规调研
 -> 现场业务调研
 -> 角色与场景建模
 -> 业务流程梳理
 -> 领域对象建模
 -> 需求分级和版本规划
 -> PRD 编写
 -> 原型和评审
 -> 技术方案评审
 -> 研发任务拆分
 -> 测试验收设计
 -> 试点上线
 -> 数据复盘和需求迭代
```

## 3. 阶段一：需求调研

### 3.1 调研目标

调研不是简单收集“想要什么功能”，而是要明确：

- 当前企业安全管理制度如何运行。
- 哪些流程必须合规，哪些流程可优化。
- 哪些数据已经存在，在哪些系统里。
- 哪些现场动作必须留痕。
- 哪些风险控制点必须系统强制拦截。
- 哪些需求是一期开工必须，哪些可二期扩展。

### 3.2 调研对象

| 对象 | 重点问题 |
| --- | --- |
| 集团/企业安全负责人 | 安全管理目标、监管要求、指标考核、事故痛点 |
| 车间/装置负责人 | 审批边界、区域风险、交叉作业、现场协同 |
| 作业申请人 | 申请频率、填写难点、常用模板、退回原因 |
| 监护人 | 现场确认、监护检查、异常暂停、留痕方式 |
| 中控/值班人员 | 报警来源、处置流程、升级机制、交接班 |
| 承包商管理员 | 准入、资质、培训、违章、黑名单 |
| 仪表/设备人员 | 点位、阈值、报警、检维修、隔离挂牌 |
| IT/OT 管理员 | 网络边界、接口方式、账号权限、安全要求 |

### 3.3 资料清单

现场调研前应要求客户提供：

- 现行特殊作业票模板。
- 特殊作业审批制度和授权矩阵。
- 承包商准入制度、资质清单、培训考试要求。
- 重大危险源台账、分级资料、包保责任清单。
- 报警分级制度、处置预案、值班表。
- 风险分级管控清单、隐患排查清单。
- 装置、区域、设备、监测点位台账。
- DCS/SIS/GDS/FAS/视频/定位/门禁等系统接口说明。
- 监管平台数据上报要求。

### 3.4 调研输出

| 产物 | 用途 |
| --- | --- |
| 现状流程图 | 识别人工环节、重复录入和风险断点 |
| 痛点清单 | 支撑需求优先级排序 |
| 制度差异表 | 判断哪些流程配置化，哪些定制开发 |
| 系统接口清单 | 支撑技术方案和集成工作量 |
| 数据字典初稿 | 支撑主数据治理和迁移 |
| 风险控制点清单 | 支撑规则引擎和验收标准 |

## 4. 阶段二：业务建模

## 4.1 业务域拆分

建议按以下业务域组织需求，避免把平台做成杂乱功能集合：

| 业务域 | 核心问题 |
| --- | --- |
| 安全基础域 | 谁、在哪里、操作什么对象 |
| 作业许可域 | 什么作业、什么风险、谁审批、如何现场确认 |
| 重大危险源域 | 哪些重大风险对象、状态如何、谁负责 |
| 报警事件域 | 发生了什么异常、谁处理、是否闭环 |
| 承包商域 | 外来单位和人员是否具备资格 |
| 双重预防域 | 风险如何管控、隐患如何整改 |
| 集成数据域 | 哪些系统提供实时数据和主数据 |
| 审计合规域 | 关键动作是否可追溯、可举证 |

## 4.2 用户旅程

### 4.2.1 高风险作业用户旅程

```text
申请人选择作业类型
 -> 填写区域、设备、时间、人员、承包商
 -> 系统自动带出风险和措施
 -> 作业负责人补充 JSA
 -> 审批人按风险等级审批
 -> 现场人员扫码签到
 -> 气体检测和措施确认
 -> 许可人批准开工
 -> 作业中监护和异常上报
 -> 完工验收
 -> 票证归档和指标统计
```

关键需求点：

- 申请要快，能复用历史作业模板。
- 审批要准，按作业等级、区域、时间和承包商动态路由。
- 现场要真，到场、定位、照片、签名、检测数据不能后补造假。
- 异常要能停，报警、违章、气体异常时要暂停作业并留痕。

### 4.2.2 报警处置用户旅程

```text
报警触发
 -> 系统去重、分级、关联对象
 -> 值班人员确认
 -> 查看趋势、视频、附近作业和人员
 -> 派发处置任务
 -> 现场反馈原因和措施
 -> 关闭或升级
 -> 复盘重复报警和根因
```

关键需求点：

- 报警必须少而准，不能让用户淹没在重复报警里。
- 报警上下文必须完整，包括点位、设备、危险源、作业票、视频、人员。
- 关闭报警必须有原因、证据和权限。

### 4.2.3 承包商准入用户旅程

```text
承包商提交单位资料
 -> 业主审核资质和合同
 -> 录入人员和证书
 -> 参加培训考试
 -> 绑定门禁/定位
 -> 参与作业
 -> 记录违章和绩效
 -> 年度复审或清退
```

关键需求点：

- 承包商管理不是静态台账，必须与作业票、门禁、培训、违章联动。
- 证书、培训、黑名单是作业许可的前置拦截条件。

## 5. 阶段三：需求分级

建议使用 MoSCoW 方法分级。

| 等级 | 定义 | 一期示例 |
| --- | --- | --- |
| Must | 不做无法上线或不合规 | 八大特殊作业票、审批、现场确认、重大危险源档案、报警闭环 |
| Should | 强烈建议一期做，否则影响价值 | 承包商资质校验、气体检测、移动端、电子签名、基础报表 |
| Could | 有价值但可后移 | 视频 AI 联动、人员定位电子围栏、GIS/3D 大屏 |
| Won't | 当前版本不做 | 完整 PHA/HAZOP、LOPA、复杂 AI 风险预测 |

## 6. PRD 推荐结构

每个模块 PRD 应保持统一结构：

```text
1. 背景与目标
2. 术语定义
3. 用户角色与权限
4. 业务流程
5. 功能清单
6. 页面与交互说明
7. 字段与表单规则
8. 状态机
9. 业务规则
10. 通知与待办
11. 接口与数据来源
12. 报表与指标
13. 异常场景
14. 审计与安全要求
15. 验收标准
16. 非功能需求
17. 版本范围与不做事项
```

## 7. 模块 PRD 设计思路

## 7.1 危险工作票 PRD

### 目标

把特殊作业从“纸质审批”升级为“风险识别、许可控制、现场监护、异常暂停、完工验收”的全过程闭环。

### 页面清单

| 页面 | 说明 |
| --- | --- |
| 作业票列表 | 查询、筛选、状态跟踪、批量导出 |
| 新建作业票 | 选择作业类型、作业区域、设备、时间、承包商 |
| 风险分析 | JSA/JHA、风险矩阵、措施推荐 |
| 审批详情 | 审批记录、意见、退回、加签 |
| 现场许可 | 签到、定位、气体检测、措施确认、照片 |
| 作业监护 | 检查记录、异常暂停、恢复、延期 |
| 完工验收 | 清场确认、设备恢复、验收签名 |
| 作业日历 | 按区域、时间查看作业冲突 |

### 关键业务规则

- 作业票必须绑定作业区域和计划时间。
- 动火、受限空间等作业必须配置气体检测有效期。
- 人员资质、承包商准入、培训有效期不满足时不得提交或许可。
- 现场许可必须校验定位或二维码/NFC 到场。
- 作业超出计划结束时间前应提醒延期，超时未延期自动暂停。
- 作业中发生关联区域高等级报警时触发复核任务。

### 验收标准

- 能按八类特殊作业创建、审批、许可、暂停、恢复、验收和归档。
- 每个关键节点能查看操作人、时间、位置、签名和附件。
- 不满足资质、培训、气体检测、报警条件时系统能拦截。
- 作业票状态流转符合状态机，不允许非法跳转。

## 7.2 重大危险源 PRD

### 目标

建立重大危险源一源一档，实现风险对象、监测点位、报警、巡检、作业、隐患和责任人的统一视图。

### 页面清单

| 页面 | 说明 |
| --- | --- |
| 危险源台账 | 查询、分级、备案、责任人 |
| 危险源详情 | 档案、点位、报警、作业、隐患、预案 |
| 实时监测 | 点位实时值、趋势、阈值 |
| 屏障管理 | 安全设施、联锁、消防、巡检状态 |
| 风险地图 | 按区域展示危险源和风险等级 |

### 关键业务规则

- 每个重大危险源必须绑定责任人、区域、等级和应急预案。
- 关键监测点位离线超过阈值应触发报警或待办。
- 危险源区域存在未关闭高等级报警时，应限制高风险作业许可。
- 安全设施失效时应生成补偿措施或隐患整改任务。

### 验收标准

- 危险源档案字段完整，能关联监测点位和责任人。
- 实时点位数据能展示当前值、单位、状态和历史趋势。
- 报警、作业票、隐患能在危险源详情中聚合展示。

## 7.3 报警系统 PRD

### 目标

将工业报警、视频 AI、人员定位、作业异常和业务规则事件统一进入报警中心，实现分级、去重、处置、升级、关闭和复盘。

### 页面清单

| 页面 | 说明 |
| --- | --- |
| 实时报警列表 | 按等级、区域、来源、状态筛选 |
| 报警详情 | 点位、趋势、视频、作业、人员、预案 |
| 处置任务 | 确认、派发、反馈、关闭 |
| 报警规则 | 阈值、分级、去重、抑制、升级 |
| 报警统计 | 高频报警、确认时长、处置时长、误报率 |

### 关键业务规则

- 同一来源、同一类型、短时间重复报警应合并。
- 一级报警必须通知值班负责人和区域负责人。
- 超时未确认或未处置必须升级。
- 报警关闭必须填写原因和处置结果。
- 报警规则、阈值、抑制策略变更必须审计。

### 验收标准

- 多来源报警能进入统一列表并分级展示。
- 报警能完成确认、派发、处置、关闭和升级。
- 能查看报警趋势、关联对象和处置记录。

## 7.4 承包商系统 PRD

### 目标

管控外来单位和人员从准入、培训、证书、门禁、作业到绩效评价的全生命周期风险。

### 页面清单

| 页面 | 说明 |
| --- | --- |
| 承包商单位台账 | 单位信息、资质、合同、准入状态 |
| 承包商人员台账 | 人员、工种、证书、培训、门禁 |
| 资质证书管理 | 到期提醒、审核、停权 |
| 培训考试 | 课程、考试、合格记录 |
| 违章与绩效 | 违章记录、整改、评分、黑名单 |

### 关键业务规则

- 单位资质过期时，旗下人员不得参与新增作业。
- 人员证书或培训过期时，作业票选择人员时应拦截。
- 黑名单人员不得进场和参与作业。
- 违章达到阈值时自动触发复训或停权。

### 验收标准

- 承包商单位、人员、资质、培训、违章数据可完整维护。
- 作业票能实时校验承包商和人员准入状态。
- 证书到期和培训过期能提醒并影响准入。

## 8. 需求到开发任务拆分

建议按“业务闭环 + 技术层”拆分，而不是按页面简单分工。

### 8.1 研发 Epic

| Epic | 说明 |
| --- | --- |
| E1 基础主数据 | 组织、人员、区域、设备、承包商基础数据 |
| E2 权限与审计 | 登录、角色、数据权限、操作日志 |
| E3 作业票核心流程 | 创建、提交、审批、许可、验收 |
| E4 作业风险规则 | 资质、培训、气体检测、报警、冲突作业校验 |
| E5 重大危险源 | 档案、点位、趋势、风险视图 |
| E6 报警中心 | 接入、分级、去重、派发、处置 |
| E7 移动端现场作业 | 签到、确认、拍照、签名、监护 |
| E8 承包商准入 | 单位、人员、证书、培训、绩效 |
| E9 集成接口 | HR/OA/EAM/DCS/GDS/视频/定位 |
| E10 报表大屏 | 指标、态势、统计、导出 |

### 8.2 用户故事模板

```text
作为 <角色>
我希望 <完成某个动作>
以便 <达成业务价值>

验收条件：
- Given <前置条件>
- When <用户操作或系统事件>
- Then <系统结果>
```

示例：

```text
作为作业申请人
我希望在新建动火作业票时选择承包商人员
以便系统自动校验其是否具备作业资格

验收条件：
- Given 承包商人员的焊工证已过期
- When 申请人在动火票中选择该人员
- Then 系统禁止选择，并提示证书过期原因
```

## 9. 原型设计步骤

1. 先画业务流程，不先画页面。
2. 明确每个页面的用户角色和使用场景。
3. 优先设计高频现场动作：新建作业票、现场许可、报警确认、承包商人员选择。
4. 每个关键按钮都要对应状态变化或业务规则。
5. 移动端原型必须体现少填、扫码、拍照、定位、签名。
6. 大屏只展示可追溯的数据，不做无业务闭环的装饰性指标。

## 10. 测试与验收设计

### 10.1 测试类型

| 测试类型 | 重点 |
| --- | --- |
| 功能测试 | 表单、流程、状态、权限 |
| 规则测试 | 资质、培训、气体、报警、交叉作业拦截 |
| 集成测试 | 工业数据、门禁、定位、视频、OA/HR/EAM |
| 移动端测试 | 弱网、扫码、定位、拍照、签名 |
| 性能测试 | 报警吞吐、点位数据写入、列表查询、大屏刷新 |
| 安全测试 | 越权、接口签名、审计、敏感信息脱敏 |
| UAT | 现场角色按真实流程试运行 |

### 10.2 核心验收用例

| 场景 | 验收点 |
| --- | --- |
| 动火作业正常闭环 | 申请、审批、气体检测、许可、监护、验收、归档 |
| 证书过期拦截 | 承包商人员证书过期时禁止加入作业 |
| 气体检测不合格拦截 | 检测不合格时禁止许可 |
| 区域报警联动 | 区域高等级报警时限制或暂停作业 |
| 报警处置闭环 | 报警确认、派发、处置、关闭、升级 |
| 重大危险源聚合视图 | 档案、点位、报警、作业、隐患可关联查看 |
| 权限隔离 | 不同厂区/区域用户只能看授权数据 |
| 审计追溯 | 关键操作可追溯到人、时间、终端和内容 |

## 11. 上线实施步骤

### 11.1 上线准备

- 清洗组织、人员、区域、设备、承包商、点位主数据。
- 配置作业票模板、审批流、风险库、安全措施库。
- 配置承包商资质、人员证书、培训有效期规则。
- 配置报警分级、派发、升级和通知规则。
- 完成接口联调和历史数据导入。
- 组织关键用户培训和试运行。

### 11.2 试点上线

建议先选择一个高风险但边界清晰的装置或区域：

- 作业频率较高，能快速验证价值。
- 重大危险源和报警点位相对完整。
- 现场管理团队配合度高。
- 接口系统数量可控。

### 11.3 推广上线

试点稳定后推广到全厂：

- 固化模板和规则。
- 建立问题反馈和版本迭代机制。
- 建立日/周/月运行指标。

## 13. 一期需求边界建议

### 13.1 一期必须做

- 基础主数据和权限。

- 承包商和人员资质校验。

- 移动端关键现场动作。

### 13.2 一期暂缓

- 完整 PHA/HAZOP 和 LOPA。
- 复杂三维可视化。
- AI 自动生成风险分析结论。
- 全量设备完整性管理。
- 复杂集团多租户运营计费。

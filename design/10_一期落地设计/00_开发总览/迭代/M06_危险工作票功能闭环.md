## 1. 目标与边界

**Must**：动火 + 受限空间 Web 端闭环（创建→审批→Web 模拟许可→验收→关闭）；规则嵌入 eligibility / area-active-check / 措施 / 气体。

**Won't**：移动端 UI、复杂审批流、CA 签名、PDF 归档、八大票种同等深度。

## 2. 依赖（第 1～3 迭代已交付）

| 能力 | 用法 |
| --- | --- |
| `eligibility-check` | 提交、许可前 |
| `area-active-check` | 许可前硬阻断（minLevel=LEVEL_2） |
| `WORK_PERMIT_TYPE` 字典 | 作业类型 |
| 主数据 area/unit/equipment | 作业地点 |

## 3. 功能闭环

```text
创建作业票草稿
 -> 维护作业信息和人员
 -> 资格和基础规则预检
 -> 风险分析和安全措施
 -> 提交审批
 -> 审批通过进入待许可
 -> 气体检测、签到、措施确认
 -> 现场许可开工
 -> 作业中监护、暂停、恢复
 -> 完工验收
 -> 关闭归档和审计追溯
```

## 4. 状态机

```text
DRAFT ──submit──▶ APPROVING ──approve──▶ PENDING_SITE_PERMIT ──site-permit──▶ IN_PROGRESS
  ▲                    │ return                              ├──suspend──▶ SUSPENDED
  └── RETURNED ◀───────┘                                     └──▶ PENDING_ACCEPTANCE ──▶ CLOSED
```

非法流转 → HTTP 409。

## 5. 规则阻断点

| 规则 | 检查点 |
| --- | --- |
| 承包商/人员准入 | submit、site-permit |
| 区域高等级报警 | site-permit |
| 安全措施未确认 | submit、site-permit |
| 气体不合格/超期 | site-permit |

`POST /api/work-permits/{id}/pre-check`（checkPoint: SUBMIT | SITE_PERMIT）→ `{ passed, reasons[] }`

> **范围**：只做设计输出，不包含代码实现。

## 1. 一期目标

一期目标是支撑试点区域上线运行，形成“基础数据可用、承包商可校验、危险源可关联、报警可闭环、作业票可现场许可、移动端可留痕、报表可验收”的最小业务闭环。

## 3. 全局接口约定

| 项 | 约定 |
| --- | --- |
| 网关前缀 | 业务接口统一经 `/api/**` 暴露，内部服务按模块拆分。 |
| 返回结构 | 统一 `ResponseVO<T>`，列表分页使用 `PageResult<T>`。 |
| 鉴权上下文 | 网关透传用户、租户、组织、角色、数据权限等上下文 Header。 |
| 时间格式 | 请求与响应使用 ISO-8601 或 `yyyy-MM-dd HH:mm:ss`，同一接口内保持一致。 |
| 幂等要求 | 报警接入、移动草稿同步、附件上传、关键状态流转需要业务幂等键或状态校验。 |
| 审计要求 | 新增、修改、删除、状态流转、审批、许可、关闭、配置变更、权限变更必须写审计。 |
| 错误语义 | 参数错误返回 400；未认证 401；无权限 403；非法状态流转 409；上游不可用返回可解释业务错误。 |
| 规则返回 | 规则接口必须返回 `passed`、`reasons[]`、`severity`、`suggestion`，供 Web 和移动端直接展示。 |

### 3.1 通用请求头

| Header | 必填 | 说明 |
| --- | --- | --- |
| `Authorization` | 是 | Bearer Token。 |
| `X-Tenant-Id` | 是 | 租户或企业标识。 |
| `X-User-Id` | 是 | 当前用户 ID，由网关注入。 |
| `X-Org-Id` | 否 | 当前组织。 |
| `X-Client-Type` | 否 | `WEB`、`MOBILE`、`DASHBOARD`、`INTERNAL`。 |
| `X-Request-Id` | 否 | 链路追踪与幂等辅助。 |

### 3.2 通用响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "req-202605270001"
}
```

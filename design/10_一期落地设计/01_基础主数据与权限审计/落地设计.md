# 基础主数据与权限审计落地设计

## 1. 模块目标

为一期所有业务模块提供统一的组织、人员、区域、设备、点位、权限和审计底座。该模块必须最先交付，否则作业票、报警、重大危险源和承包商无法形成统一对象关系。

## 2. 功能范围

| 子模块 | 一期范围 |
| --- | --- |
| 租户体系 | 租户、企业、厂区隔离，租户管理员，租户级配置 |
| 注册登录 | 本地账号、管理员邀请、SSO 登录、退出、Token 刷新 |
| 通用 SSO | OIDC/OAuth2/SAML/CAS/LDAP/AD 适配预留，统一用户映射 |
| 组织用户 | 集团、企业、厂区、部门、班组、用户、岗位、在职状态 |
| 区域设备 | 厂区、区域、装置、设备、设备状态、风险等级 |
| 监测点位 | 点位编码、来源系统、原始点号、单位、阈值、对象绑定 |
| 权限 | 租户角色、菜单、页面、按钮、接口权限、数据权限 |
| 审计 | 操作日志、关键数据变更审计、登录日志 |

## 3. 关键流程

### 3.1 主数据维护流程

```text
新增/导入主数据
 -> 字段校验和编码唯一性校验
 -> 保存草稿或直接启用
 -> 业务模块引用
 -> 变更或停用
 -> 记录审计和影响范围
```

### 3.2 权限配置流程

```text
创建角色
 -> 分配菜单、页面和按钮权限
 -> 分配接口权限
 -> 配置数据范围
 -> 绑定用户或岗位
 -> 权限生效
 -> 记录权限变更审计
```

### 3.3 SSO 登录流程

```text
用户访问系统
 -> 选择租户或根据域名识别租户
 -> 跳转企业身份源
 -> 企业身份源完成认证
 -> 回调平台并校验票据/Token
 -> 根据外部用户标识映射本地用户
 -> 加载租户、角色、页面权限和数据权限
 -> 签发平台访问 Token
 -> 进入系统
```

### 3.4 管理员邀请注册流程

```text
租户管理员创建邀请
 -> 填写手机号/邮箱/所属组织/岗位/角色
 -> 系统发送邀请链接或初始账号
 -> 用户完成密码设置和基础信息确认
 -> 账号启用
 -> 首次登录后按角色加载权限
```

## 6. 注册登录与 SSO 设计

### 6.1 登录方式

| 方式 | 适用场景 | 一期要求 |
| --- | --- | --- |
| 本地账号密码 | 试点、实施、兜底登录 | 支持，密码加密存储 |
| 管理员邀请注册 | 企业内部用户开通 | 支持，禁止开放匿名自注册 |
| SSO 登录 | 企业已有统一身份认证 | 支持通用协议适配 |
| LDAP/AD 同步 | 企业目录同步账号 | 预留或按现场接口落地 |
| 移动端登录 | 现场作业 | 使用平台 Token，可复用 SSO 登录态 |

一期不建议开放公网匿名注册。用户由租户管理员创建、批量导入、HR/AD 同步或邀请注册，避免承包商和内部用户绕过准入流程。

### 6.2 通用 SSO 适配

SSO 采用“平台统一认证入口 + 租户身份源配置 + 本地用户映射”的设计。不同企业可以绑定不同身份源，但业务模块只识别平台用户、租户、角色和权限。

| 协议 | 一期定位 |
| --- | --- |
| OIDC/OAuth2 | 优先支持，适合现代 IAM、企业微信、钉钉、统一门户 |
| SAML 2.0 | 预留，适合传统企业 IdP |
| CAS | 预留，适合已有高校/企业门户 |
| LDAP/AD | 用于用户同步或密码认证集成 |

用户映射优先级：
1. 外部身份唯一 ID。
2. 员工号。
3. 手机号或邮箱。
4. 租户内用户名。

映射失败时不自动创建可用账号，默认进入待绑定或待审核状态，由租户管理员确认组织、岗位、角色和数据范围。

### 6.3 Token 与会话

- Web 和移动端统一使用平台访问 Token。
- Token 中只放租户、用户、会话和必要权限版本号，不放大体量权限明细。
- 用户角色、页面权限、数据权限变更后，权限版本递增，旧 Token 在下一次鉴权时失效或刷新。
- 退出登录需清理平台会话；SSO 场景按租户配置决定是否联动企业身份源退出。

### 6.4 登录安全

- 密码必须加盐哈希存储，不保存明文和可逆密文。
- 支持登录失败锁定、验证码或二次校验预留。
- 支持租户级密码策略：长度、复杂度、有效期、历史密码限制。
- 登录日志记录租户、用户、IP、终端、结果和失败原因。
- 禁用、离职、锁定用户不得登录，也不得参与新业务流程。

## 7. 多租户模型

### 7.1 租户边界

租户是平台最高业务隔离边界。一期默认采用共享应用、共享数据库、按 `tenant_id` 逻辑隔离的模式；若客户要求物理隔离，可在部署层独立实例或独立库。

所有业务主表必须包含 `tenant_id`。跨租户访问默认禁止，平台运维人员如需跨租户排障，必须走受控运维角色并记录审计。

### 7.2 租户内组织层级

```text
租户
 -> 集团/企业
 -> 厂区
 -> 部门/车间
 -> 班组
 -> 用户/岗位
```

租户内可按企业、厂区、区域、装置继续做数据权限收敛。集团型客户可以在一个租户内管理多企业，也可以按企业拆分多个租户，需在实施阶段确认。

### 7.3 租户级配置

| 配置 | 是否租户隔离 |
| --- | --- |
| 身份源 | 是 |
| 角色和权限 | 是 |
| 菜单启用范围 | 是 |
| 字典和作业票模板 | 是 |
| 审批流和规则 | 是 |
| 通知通道 | 是 |
| 附件存储策略 | 是 |

## 8. 权限设计

### 8.1 权限模型

权限由四层组合：

1. 租户权限：用户只能访问所属租户数据和配置。
2. 页面权限：控制菜单、路由、页面入口和可见模块。
3. 操作权限：控制按钮、批量操作、导出、审批、许可、关闭等动作。
4. 数据权限：控制企业、厂区、区域、装置、班组和本人相关数据范围。

### 8.2 页面权限

页面权限同时控制前端路由和后端接口资源，不允许只靠前端隐藏。

| 权限对象 | 示例 |
| --- | --- |
| 一级菜单 | 作业许可、报警中心、承包商、重大危险源、系统管理 |
| 页面路由 | 作业票列表、作业票详情、报警详情、承包商人员详情 |
| 页面区块 | 报警趋势、作业审批记录、审计记录、导出区域 |
| 按钮动作 | 新增、编辑、删除、提交、审批、许可、暂停、恢复、关闭、导出 |
| 接口资源 | `/work-permits/{id}/approve`、`/alarms/{id}/close` |

前端登录后通过权限接口获取菜单树、路由清单和按钮权限码；后端接口仍按用户 Token、角色、权限码和数据范围二次校验。

### 8.3 角色设计

| 角色 | 权限重点 |
| --- | --- |
| 平台运维管理员 | 租户开通、系统运维，不默认拥有业务数据权限 |
| 租户管理员 | 本租户组织、用户、角色、配置管理 |
| 系统管理员 | 组织、用户、权限、字典、流程配置 |
| 安全管理员 | 作业票监管、报警、重大危险源、报表 |
| 装置/车间负责人 | 本区域作业审批和风险查看 |
| 作业申请人 | 创建和维护本人作业票 |
| 许可人 | 现场许可、验收、暂停和恢复 |
| 监护人 | 现场监护、异常上报 |
| 中控/值班人员 | 报警确认、派发、处置跟踪 |
| 承包商管理员 | 本单位人员、证书、培训和资料维护 |
| 企业领导 | 授权范围内态势和报表查看 |

### 8.4 数据权限

数据权限按企业、厂区、区域、装置逐级收敛。用户只能查看授权范围内的作业票、报警、危险源、承包商作业记录和报表明细。

| 数据范围 | 说明 |
| --- | --- |
| 全租户 | 租户内全部业务数据，通常只给租户管理员或企业领导 |
| 本企业 | 所属企业范围 |
| 本厂区 | 所属厂区范围 |
| 本区域 | 授权区域及下级区域 |
| 本装置 | 授权装置 |
| 本部门/班组 | 所属组织及下级组织 |
| 本人相关 | 本人创建、审批、监护、许可或参与的数据 |
| 承包商本单位 | 承包商管理员仅访问本承包商单位数据 |
| 自定义 | 多区域、多装置、多角色组合授权 |

数据权限执行原则：
- 列表查询必须追加租户和数据范围过滤。
- 详情查询必须二次校验用户是否有该对象访问权。
- 导出、报表和大屏也必须受数据权限控制。
- 审批、许可、报警处置等操作还需叠加场景权限。

### 8.5 场景权限

| 场景 | 权限约束 |
| --- | --- |
| 作业票审批 | 用户必须是当前审批节点处理人或被授权代理人 |
| 现场许可 | 用户必须具备许可人角色，且在作业票许可人范围内 |
| 报警确认 | 用户必须具备值班或报警处置角色 |
| 阈值修改 | 仅设备/仪表管理员或授权安全管理员可操作 |
| 黑名单 | 仅承包商高级管理员或安全管理员可操作 |

## 9. 审计设计

### 9.1 必审计动作

- 租户开通、停用、身份源配置变更。
- 用户注册、邀请、启用、禁用、离职、锁定、解锁。
- 用户、角色、数据权限变更。
- 页面权限、按钮权限、接口权限变更。
- 区域、设备、点位新增、修改、停用。
- 点位阈值修改。
- 登录成功、登录失败、退出、SSO 映射失败。
- 数据导入、导出。

## 12. 验收标准

- 支持租户级登录入口和身份源配置，用户只能访问所属租户。
- 支持本地账号登录、管理员邀请注册和 SSO 登录流程。
- SSO 用户可映射到本地用户，并加载租户、角色、页面权限和数据权限。
- 用户角色或权限变更后，页面入口、按钮动作和接口鉴权同步生效。
- 所有业务数据查询默认按 `tenant_id` 隔离。
- 数据权限可按企业、厂区、区域、装置、本人相关和承包商本单位控制。
- 用户可按组织查询，禁用用户无法登录和参与新流程。
- 区域、装置、设备、点位可被作业票、报警和重大危险源引用。
- 区域停用后不可新建关联作业。
- 未授权用户无法访问越权数据。
- 关键操作可追溯到人、时间、终端、操作前后内容。

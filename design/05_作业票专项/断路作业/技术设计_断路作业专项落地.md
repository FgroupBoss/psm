# 断路作业 · 专项落地技术设计

## 1. 设计结论

在 `psm-operation-api.workpermit.roadbreak` 下新增断路详情、交通方案、现场布控、通知送达和恢复验收。断路对同区域作业产生横向影响，必须接入 SIMOPS。

## 2. 数据模型

| 表 | 用途 | 核心字段 |
| --- | --- | --- |
| `road_break_detail` | 断路详情 | `permit_id, road_id, area_geo_json, reason, start_at, end_at, responsible_unit` |
| `road_break_traffic_plan` | 交通方案 | `permit_id, detour_geo_json, emergency_lane_geo_json, plan_ref, confirmed` |
| `road_break_site_control` | 现场布控 | `permit_id, item_code, position, result, attachment_ref` |
| `road_break_notification` | 通知送达 | `permit_id, receiver_type, receiver_id, delivery_status, delivered_at` |
| `road_break_restoration` | 恢复验收 | `permit_id, road_restored, signage_restored, cleared, accepted_at` |

## 3. 接口与规则

| HTTP | Path |
| --- | --- |
| GET/PUT | `/api/work-permits/{id}/road-break-detail` |
| GET/PUT | `/api/work-permits/{id}/road-break/traffic-plan` |
| GET/POST | `/api/work-permits/{id}/road-break/site-controls` |
| GET/POST | `/api/work-permits/{id}/road-break/notifications` |
| POST | `/api/work-permits/{id}/road-break/restoration` |
| POST | `/api/work-permits/{id}/road-break/pre-check` |

`SUBMIT` 校验交通方案和通知范围；`SITE_PERMIT` 校验路障、标志、围挡、照明、绕行和应急通道；`MONITOR` 校验应急通道；`ACCEPTANCE` 校验道路恢复。

## 4. 事件、安全与测试

- 事件：`ROAD_BREAK_STARTED`、`EMERGENCY_LANE_BLOCKED`、`ROUTE_CHANGED`、`RESTORED`、`CLOSED`。
- 地图、通知和应急通道数据按区域权限隔离；路线变化必须版本化。
- 测试覆盖方案缺失、通知未送达、应急通道占用、标志缺失、路线变化、SIMOPS 和恢复验收。

## 5. 上线

批次 `S3`，开关 `psm.road-break.enabled=false`。先维护道路和应急通道主数据，再启用通知和 SIMOPS 联动。

## 1. 结论

流程图「当前流程」展示的是**动火作业票**面向现场与管理端的全生命周期可视化，将 GB 30871 动火作业要求的「申请 → 风险辨识与交底 → 审批许可 → 现场开工 → 监护执行 → 完工验收 → 关闭归档」拆成 **9 个可感知业务节点**，其中「安全分析及交底」「安全交底签字」「待作业」「待关闭」是现有一期动火状态机**未独立建模或未在前端完整呈现**的关键环节。

**专项建设目标**：在不动 M06 动火核心闭环的前提下，补齐动火票「流程可视化 + 交底签字 + 待关闭」能力，使 UI 流程图与后端状态/子阶段一致；**不扩展至其他票种或联票场景**。

| 维度 | 结论 |
| --- | --- |
| 流程图性质 | 只读进度视图 + 节点下钻入口，不是独立审批引擎 |
| 票种范围 | **仅 `permit_type = 动火`**（或字典 `HOT_WORK` / 等价编码） |
| 与现状态机关系 | 9 个展示节点映射到 8～10 个后端状态/子阶段，允许「一节点多状态」聚合展示 |
| 优先缺口 | 动火交底签字、待关闭两阶段、当前流程弹窗 |
| 一期可保留 | 动火 pre-check、气体检测、区域报警阻断、timeline API |
| 建议分期 | Phase A：动火流程视图；Phase B：动火交底签字 + 待关闭 |

## 2. 业务目标

### 2.1 要解决什么问题

1. **管理可视**：安全管理人员、装置负责人在列表页即可看到每张票「走到哪一步、卡在谁、下一步做什么」，减少反复打开详情页核对。
2. **交底可证**：GB 30871 要求作业前安全交底并签字确认；流程图将「分析交底」与「交底签字」独立成段，便于审计倒查。
3. **许可与开工分离**：「审批中」与「待作业」分离，对应制度上「纸面批准」与「现场条件满足后开工」的差异，避免审批通过即视为已开工。
4. **验收与关闭分离**：「待验收」与「待关闭」分离，支持作业负责人先报完工、许可人/区域负责人验收、安全或装置负责人最终关闭归档。

### 2.2 成功指标（专项验收，动火票）

| 指标 | 目标 |
| --- | --- |
| 流程节点与后端状态一致性 | 动火票 100% 可映射，无「界面显示待作业、后端仍审批中」类偏差 |
| 交底签字完成率（已提交动火票） | 试点区域 ≥ 95% |
| 关键节点证据链完整率 | 交底、许可、验收、关闭均含人员+时间+签名/附件 |
| 非法状态跳转拦截 | 与现网一致，HTTP 409 + 明确原因 |
| 非动火票不受影响 | 其他票种列表/详情不出现本专项流程图，或沿用原 M06 展示 |

### 3.2 各节点功能说明

| 展示节点 | 业务含义 | 典型操作 | 关键产出/证据 |

| **申请** | 动火票创建与基础信息填报 | 选动火级别/区域/时间/人员/承包商；保存草稿 | 票号（如 `SW-DH-YYYYMMDD-SEQ`）、基础字段、附件 |
| **安全分析及交底** | JSA/JHA 风险辨识 + 交底内容编制 | 维护风险步骤、措施；填写交底要点；组织交底 | 风险分析记录、措施清单、交底文本/附件 |
| **安全交底签字** | 参与人员知悉风险并确认 | 作业人员、监护人、作业负责人等签字 | 多人签名记录、签字时间 |

| **待作业** | 审批通过，现场开工条件准备 | 签到、**动火前气体检测**、防火措施现场确认、许可人批准开工 | 检测记录、现场确认、开工许可签名 |
| **作业中** | 正式施工/作业执行 | 监护记录、巡检、异常上报 | 监护日志、照片、定位 |
| **暂停中** | 作业临时中止 | 暂停登记、原因、恢复前复核 | 暂停/恢复记录、复核项 |
| **待验收** | 作业完成，等待验收 | 作业负责人报完工、清场确认 | 完工说明、清场确认项 |
| **待关闭** | 验收通过，等待最终关闭 | 许可人/区域负责人/安全管理员关闭 | 验收签名、关闭确认 |
| **作业关闭** | 全流程结束归档 | 只读查看、导出 PDF/监管报送 | 归档快照、审计链 |

## 4. 与现网实现映射及差距

### 4.1 后端状态机（已交付 M06）

```text
DRAFT → APPROVING → PENDING_SITE_PERMIT → IN_PROGRESS ⇄ SUSPENDED
  ↑         │ return                                    ↓
  └── RETURNED                                          PENDING_ACCEPTANCE → CLOSED
APPROVING ──reject──▶ CLOSED
IN_PROGRESS/SUSPENDED ──terminate──▶ CLOSED
```

### 4.2 展示节点 ↔ 后端映射

| 展示节点 | 现网状态/阶段 | 差距 |
| --- | --- | --- |
| 申请 | `DRAFT` | 基本一致；缺独立「已申请未分析」子阶段标识 |
| 安全分析及交底 | `DRAFT` 内子阶段 | **未独立状态**；风险分析 API 已有，交底内容/交底完成标记未建模 |
| 安全交底签字 | 无 | **缺失**；无 `permit_disclosure_sign` 类表与完成门槛 |
| 审批中 | `APPROVING` | 一致 |
| 待作业 | `PENDING_SITE_PERMIT` | 语义接近但**命名不一致**；现场准备（气体/签到）均折叠在该状态 |
| 作业中 | `IN_PROGRESS` | 一致 |
| 暂停中 | `SUSPENDED` | 一致 |
| 待验收 | `PENDING_ACCEPTANCE` | 一致（负责人 REQUEST_ACCEPTANCE 后进入） |
| 待关闭 | 无独立状态 | **缺失**；现网验收人一次操作直接从 `PENDING_ACCEPTANCE` → `CLOSED` |
| 作业关闭 | `CLOSED` | 一致 |

### 4.3 前端能力差距

| 能力 | 现网 | 目标 |
| --- | --- | --- |
| 流程图弹窗 | 无；仅有 timeline 列表 | 垂直/水平流程图 + 节点高亮 |
| 状态中文展示 | 枚举英文 | 与流程图节点中文一致 |
| 票种范围 | 通用作业票 UI | 动火票专用流程图与交底 |
| 交底签字页 | 无 | Web + 移动端签字（动火） |

## 5. 角色与场景

### 5.1 角色

| 角色 | 流程图中的主要触点 |
| --- | --- |
| 作业申请人 | 申请、补充资料、重新提交 |
| 作业负责人 | 安全分析、组织交底、报完工 |
| 监护人 | 交底签字、现场监护、暂停建议 |
| 作业人员（含承包商） | 交底签字、现场签到 |
| 许可人 | 待作业阶段许可开工、待验收/待关闭验收签字 |
| 装置/车间负责人 | 审批中、待关闭（可配置） |
| 安全管理员 | 监管、强制终止、关闭复核、流程配置 |
| 承包商管理员 | 人员资质维护（间接影响申请/待作业门槛） |

### 5.2 典型场景（动火单票）

**场景 A：外委组织在气化装置二级动火（截图样例对应动火票部分）**

- 创建**动火安全作业票**，票号如 `SW-DH-20260528-001`，动火级别二级，作业区域气化装置。
- 安全分析及交底覆盖动火风险（火源、可燃物、介质、周边设备等）；交底签字由作业人员、监护人、作业负责人等完成。
- 审批按动火级别路由（二级动火审批链）；提交/许可前执行 pre-check（资质、措施、气体等）。
- 「当前流程」仅展示**本张动火票**的 9 节点进度；若现场另有临电等票，由各自专项流程独立展示，不在本弹窗聚合。

**场景 B：外委组织动火 — 许可前阻断**

- 承包商人员准入、证书、培训在「申请」「待作业」两节点前被 `eligibility-check` 拦截。
- 待作业阶段：区域 `LEVEL_2` 报警未关闭则阻断许可（已交付）。

**场景 C：动火作业中暂停再恢复**

- 动火暂停后恢复前，**气体检测复测**、防火措施再确认（可配置为恢复前必做，符合 GB 30871 动火中断恢复要求）。
- 流程图在「作业中」「暂停中」之间切换高亮，timeline 保留每次暂停/恢复。

**场景 D：动火完工两阶段关闭**

- 作业负责人在「作业中」提交验收 → 进入「待验收」。
- 许可人验收签字 → 进入「待关闭」。
- 装置负责人或安全管理员最终关闭 → 「作业关闭」并生成归档快照。

## 6. 主流程（专项目标态）

```text
1. 申请
   创建动火票 → 填写级别/区域/时间/人员/承包商 → 保存草稿

2. 安全分析及交底
   JSA/JHA → 风险等级 → 措施推荐与确认 → 编制交底内容

3. 安全交底签字
   推送待签 → 作业人员/监护人/负责人等签字 → 全部必签完成

4. 提交审批
   pre-check(SUBMIT) → 进入审批中

5. 审批中
   各级审批 → 通过进入待作业 / 退回 / 驳回关闭

6. 待作业
   pre-check(SITE_PERMIT) → 签到 → 动火前气体检测 → 防火/隔离措施现场确认 → 许可人签字开工

7. 作业中 ⇄ 暂停中
   监护记录 → 可暂停/恢复（可配置恢复前复测）

8. 待验收
   作业负责人报完工 → 清场确认

9. 待关闭
   许可人/验收人签字 → 可选最终关闭人确认

10. 作业关闭
    归档快照 → PDF/监管接口 → 只读
```

## 7. 异常流程

| 异常 | 触发点 | 系统行为 | 流程图展示 |
| --- | --- | --- | --- |
| 审批退回 | 审批中 | → `RETURNED`，回申请节点修改 | 高亮回「申请」或「安全分析」（可配置回退深度） |
| 审批驳回 | 审批中 | → `CLOSED`（带原因） | 终态「作业关闭（驳回）」 |
| 资质/培训失效 | 提交、待作业 | pre-check 阻断，列原因 | 保持当前节点，展示阻断徽章 |
| 气体不合格/超期 | 待作业 | 禁止许可 | 「待作业」节点红色提示 |
| 区域报警 | 待作业 | 硬阻断或升级审批 | 同上 |
| 同区域其他作业冲突 | 提交、待作业 | 若已接入 SIMOPS，动火与同区域其他票冲突时 WARN/BLOCK | 节点上显示冲突标识（**不含联票**） |
| 作业超时 | 作业中 | 提醒 → 可配置自动暂停 | 「作业中」超时角标 |
| 暂停后未恢复 | 暂停中 | 超时提醒监护人/许可人 | 「暂停中」计时 |
| 强制终止 | 作业中/暂停中 | → `CLOSED` | 关闭节点，标注终止 |
| 上游服务不可用 | pre-check | `UPSTREAM_UNAVAILABLE` | 节点不可推进，全局提示 |
| 弱网 | 移动端 | 草稿暂存；许可/交底签字须在线 | 显示「待同步」 |

## 8. 业务规则

### 8.1 节点准入（完成条件）

| 节点 | 进入条件 | 离开条件 |
| --- | --- | --- |
| 申请 | 创建票 | 必填字段完整 |
| 安全分析及交底 | 申请完成 | 风险分析完成 + 必需措施已确认 + 交底内容已保存 |
| 安全交底签字 | 分析交底完成 | 配置的全部必签角色已签 |
| 审批中 | 提交成功且 pre-check 通过 | 最后一级审批通过 |
| 待作业 | 审批通过 | 许可人现场许可（pre-check SITE_PERMIT 通过） |
| 作业中 | 许可开工 | 负责人发起验收或强制终止 |
| 暂停中 | 从作业中暂停 | 恢复 → 作业中；或终止 |
| 待验收 | 负责人提交验收 | 验收人完成验收签字 |
| 待关闭 | 验收通过 | 最终关闭人确认 |
| 作业关闭 | 关闭确认 | 终态 |

### 8.2 与 GB 30871 动火作业对齐要点

- **动火分级**：特级/一级/二级动火在申请节点必选；审批链、气体检测频次、许可人资质按级别配置。
- **气体检测**：动火前及中断恢复后须检测；分析人资质、检测位置、合格标准在「待作业」门槛校验（一期气体有效期默认 30 分钟）。
- **交底与签字**：动火作业前须完成安全交底，作业人员、监护人等签字确认；专项新增交底表与签字门槛。
- **防火措施**：动火特有措施（隔离、清理可燃物、消防器材、监护等）在「安全分析及交底」「待作业」两阶段分别确认。
- **审批分级**：特级/一级/二级动火对应不同审批层级（一期为简化审批，专项可配置扩展）。

### 8.3 可配置项（动火专项）

| 配置项 | 说明 |
| --- | --- |
| 动火流程节点 | 固定 9 节点模板，本专项不配置跨票种差异 |
| 交底必签角色 | 作业人、监护人、负责人、承包商负责人等（动火默认集） |
| 关闭模式 | 一步关闭（兼容现网）/ 两步关闭（待验收+待关闭） |
| 恢复前复测 | 动火暂停恢复是否强制气体复测（建议默认开启） |
| 动火级别审批链 | 特级/一级/二级分别绑定审批模板 |

## 9. 数据与证据

### 9.1 新增/扩展实体建议

| 实体 | 用途 | 关键字段 |
| --- | --- | --- |
| `permit_disclosure` | 交底主记录 | permit_id, content, disclosed_at, disclosed_by, attachments |
| `permit_disclosure_sign` | 交底签字 | disclosure_id, signer_id, role, sign_image, signed_at, terminal |
| `permit_phase_marker` | 子阶段标记（可选，免改主状态机） | permit_id, phase_code, completed, completed_at |

**说明**：交底/签字/待关闭数据均挂在**单张动火票** `permit_id` 下，不引入作业包表。若希望最小改动主状态机，「安全分析及交底」「安全交底签字」可用 `phase_code` 子阶段 + 提交门槛表达；「待关闭」可新增状态 `PENDING_CLOSURE` 或由 `acceptance_status` 区分「已验收待关闭」。`flow-progress` 接口须校验票种为动火，非动火票返回 404 或走通用 timeline。

### 9.2 现有表复用

| 表 | 流程节点 |
| --- | --- |
| `work_permit` | 主状态 |
| `permit_risk_analysis` | 安全分析及交底 |
| `permit_safety_measure` | 安全分析及交底 |
| `permit_approval_record` | 审批中 |
| `gas_test_record` / `permit_site_confirm` | 待作业 |
| `permit_monitor_record` | 作业中/暂停中 |
| `permit_acceptance_record` | 待验收/待关闭 |
| `permit_status_log` | 全流程 |
| `permit_archive_snapshot` | 作业关闭 |

### 9.3 证据链要求

每个节点至少沉淀：**操作人、操作时间、终端/位置、业务内容、签名或附件哈希**；流程图节点点击可直达证据详情。

| 操作 | 建议权限 |

### 10.2 审计

- 流程节点变更、子阶段完成、签字、配置变更写审计日志。
- 流程图仅为视图，所有状态变更必须经 API 并记录 `permit_status_log`。
- 交底内容修改留版本或修改前后对比（至少记录最后一次修改人/时间）。

## 11. 风险与控制点

| 风险 | 控制措施 |
| --- | --- |
| 展示状态与真实状态不一致 | 流程图由后端 `flow-progress` API 统一驱动，禁止前端自行推断 |
| 交底走过场 | 必签角色配置 + 未签完不可提交；移动端支持现场签字 |
| 审批通过即视为开工 | 「待作业」与「作业中」严格分离，许可 API 独立 |
| 非动火票误用动火流程 | API 与前端按 `permit_type` 过滤；配置与模板动火专用 |
| 动火暂停后未复测开工 | 恢复前默认强制气体复测与防火措施再确认 |
| 越权关闭 | 待关闭单独权限；关闭写归档快照 |
| 弱网假签字 | 交底签字、许可、关闭必须在线校验 |

## 14. 分期实施建议（动火专项）

### Phase A · 动火流程可视化（2～3 周）

- 后端：`flow-progress` API（票种=动火），映射现 8 状态到 9 展示节点
- 前端：动火票列表「当前流程」弹窗 + 详情 Tab
- 验收：二级动火票全流程节点高亮与 timeline 一致；非动火票不出现本弹窗

### Phase B · 动火交底与两阶段关闭（3～4 周）

- 数据：`permit_disclosure`、`permit_disclosure_sign`；可选 `PENDING_CLOSURE` 状态
- 流程：动火票提交前交底签字门槛；验收与关闭 API 拆分
- 移动端：动火交底签字页
- 验收：未签完不可提交；两阶段关闭可配置；气化装置外委动火 E2E

### 后续（另立专项，不在本文档）

- 受限空间、临电、高处等票种流程与「当前流程」模板
- 动火+临电等联票、作业包与跨票进度聚合
- 动火监管报送字段扩展（若与单票流程解耦，可独立排期）

## 15. 验收标准

| 编号 | 检查项 |
| --- | --- |
| AC-WP-FLOW-01 | **动火票**列表可打开「当前流程」弹窗，当前节点与 `work_permit.status` 映射正确 |
| AC-WP-FLOW-02 | 作业中/暂停中双向切换时，流程图高亮正确 |
| AC-WP-FLOW-03 | 节点点击可下钻到对应证据区块 |
| AC-WP-FLOW-04 | 安全分析及交底未完成时，不可进入交底签字完成态 |
| AC-WP-FLOW-05 | 交底必签角色未齐，提交审批返回 409 及原因 |
| AC-WP-FLOW-06 | 审批通过后处于「待作业」，未许可不得进入作业中 |
| AC-WP-FLOW-07 | 气体/报警/资质阻断时，待作业节点展示阻断原因 |
| AC-WP-FLOW-08 | 负责人提交验收后进入待验收；验收人签字后进入待关闭（两阶段模式） |
| AC-WP-FLOW-09 | 最终关闭后生成归档快照，票证只读 |
| AC-WP-FLOW-10 | 非动火票调用 `flow-progress` 不返回动火 9 节点模板（404 或明确错误码） |
| AC-WP-FLOW-11 | 动火票全流程关键操作可在审计日志与 timeline 追溯 |
| AC-WP-FLOW-12 | 非法状态跳转返回 409，与现网行为一致 |
| AC-WP-FLOW-13 | 特级/一级/二级动火均可走同一 9 节点流程，审批链按级别差异不影响节点结构 |

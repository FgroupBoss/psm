# 动土作业 · 专项落地技术设计

## 1. 设计结论

在 `psm-operation-api.workpermit.excavation` 下新增动土详情、地下设施、专业会签、现场检查和恢复记录。地下设施无法确认时，必须进入探测与试挖路径。

## 2. 数据模型

| 表 | 用途 | 核心字段 |
| --- | --- | --- |
| `excavation_work_detail` | 动土详情 | `permit_id, area_geo_json, depth_m, area_m2, method, drawing_ref, valid_until` |
| `excavation_underground_facility` | 地下设施 | `permit_id, facility_type, owner_unit, position, depth_m, detection_method, confirmed` |
| `excavation_countersign` | 专业会签 | `permit_id, specialty, signer_id, result, opinion, signed_at` |
| `excavation_site_check` | 现场检查 | `permit_id, stage, item_code, result, attachment_ref` |
| `excavation_restoration` | 恢复验收 | `permit_id, backfill, compaction, pavement, signage, accepted_at` |

## 3. 接口与规则

| HTTP | Path |
| --- | --- |
| GET/PUT | `/api/work-permits/{id}/excavation-detail` |
| GET/POST | `/api/work-permits/{id}/excavation/facilities` |
| GET/POST | `/api/work-permits/{id}/excavation/countersigns` |
| GET/POST | `/api/work-permits/{id}/excavation/site-checks` |
| POST | `/api/work-permits/{id}/excavation/restoration` |
| POST | `/api/work-permits/{id}/excavation/pre-check` |

`SUBMIT` 校验图纸、设施确认和专业会签；`SITE_PERMIT` 校验放线、探测、试挖、支护、临边、通道、排水和警示；`RESUME` 校验天气、土体和变化项；`ACCEPTANCE` 校验恢复。

## 4. 事件、安全与测试

- 事件：`UNDERGROUND_UNKNOWN_FOUND`、`LEAK_SUSPECTED`、`RAIN_BLOCKED`、`RESTORED`、`CLOSED`。
- GIS 和地下设施数据只读接入，现场探测结果必须保留来源和时间。
- 测试覆盖会签缺失、设施未知、机械开挖阻断、深度变化、支护失败、积水暂停和恢复验收。

## 5. 上线

批次 `S3`，开关 `psm.excavation.enabled=false`。先完成地下设施数据治理和专业会签角色配置，再灰度启用。

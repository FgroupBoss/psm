# 高处作业 · 专项落地技术设计

> **文档类型**：技术设计  
> **关联**：[需求分析](./需求分析_高处作业全生命周期.md)、[产品设计](./产品设计_高处作业流程与现场许可.md)  
> **代码落点**：`psm-operation-api` · `workpermit`

---

## 1. 设计结论

高处作业作为 `work_type = HEIGHT_WORK` 的票种专项落在 `psm-operation-api`。复用通用作业票主状态机、交底签字、审批、审计、SIMOPS 和归档能力，新增高处详情、危险因素、防护检查、环境检查和专项 pre-check。

本期不新增独立微服务，不引入通用 BPM 引擎，不从管理网反向控制 OT 系统。

## 2. 模块边界

```text
psm-operation-api
└─ workpermit
   ├─ heightwork
   │  ├─ controller       高处专项接口
   │  ├─ service          详情、检查、规则编排
   │  ├─ rule             分级分类和门槛规则
   │  ├─ integration      天气、定位等只读客户端
   │  └─ model            DTO、VO、Entity、Mapper
   ├─ common              通用票状态机、交底、审批、归档
   └─ simops              冲突扫描
```

| 模块 | 职责 |
| --- | --- |
| 高处专项 | 专项字段、规则计算、检查项、环境快照、专项门槛 |
| 通用作业票 | 主状态、人员、JSA/JHA、措施、审批、许可、监护、验收、归档 |
| 配置域 | 措施模板、审批路由、阈值、规则版本 |
| 外部集成 | 天气、定位、IAM、承包商、报警数据只读接入 |

## 5. 规则与流程引擎

### 5.1 规则入口

```java
public enum HeightWorkCheckPoint {
    SAVE,
    SUBMIT,
    SITE_PERMIT,
    RESUME,
    MONITOR
}
```

| 检查点 | 核心规则 |
| --- | --- |
| `SAVE` | 高度、位置、方式、有效期基础校验 |
| `SUBMIT` | 自动分级、A/B 类、人员资格、JSA/JHA、交底、必需措施 |
| `SITE_PERMIT` | 到场、防护、环境、天气、SIMOPS、救援、在线签字 |
| `RESUME` | 未过期、防护复核、环境复核、SIMOPS、在线签字 |
| `MONITOR` | 到期、天气变化、监护超时、异常事件 |

### 5.2 分级分类计算

```text
heightLevel = calculate(workHeightM)
riskClass = hazardFactors.isEmpty() ? A : B

if manualUpgrade:
  only allow stricter control level
  require reason
  write audit log
```

标准危险因素内置为不可删除的规则种子，企业扩展项通过配置追加。规则版本随许可和归档快照保存。

### 5.3 默认措施

扩展 `DefaultSafetyMeasuresSupport`，按 `HEIGHT_WORK + workMethod + heightLevel + riskClass` 加载：

- 登高设施合格。
- 正确使用全身式安全带，系挂点可靠。
- 安全绳、生命线、防坠器适用且检查合格。
- 临边、孔洞防护完整。
- 工具和材料采取防坠落措施。
- 下方设置警戒区并安排监护。
- 临近带电体、交叉作业按专项规则隔离。
- 四级高处通信联络和救援方案确认。

## 6. 事件与消息

| 事件 | 触发 | 处理 |
| --- | --- | --- |
| `HEIGHT_WORK_SUBMITTED` | 提交 | 创建审批待办 |
| `HEIGHT_WORK_SITE_PERMITTED` | 许可 | 记录环境、防护、规则版本快照 |
| `HEIGHT_WORK_WEATHER_BLOCKED` | 天气超限 | 阻断或通知暂停 |
| `HEIGHT_WORK_SUSPENDED` | 人工或规则暂停 | 通知负责人、许可人、安全管理员 |
| `HEIGHT_WORK_RESUME_REQUIRED` | 暂停后 | 创建复核待办 |
| `HEIGHT_WORK_EXPIRING` | 即将到期 | 提醒负责人、监护人 |
| `HEIGHT_WORK_EXPIRED` | 到期 | 禁止恢复和继续作业 |
| `HEIGHT_WORK_CLOSED` | 关闭 | 生成归档快照和报表事件 |

事件写入事务内状态日志；跨服务通知采用可靠消息或可重试任务，失败不回滚已完成的业务状态，但必须可观测和可补偿。

## 7. 权限与审计

| 操作 | 权限建议 |
| --- | --- |
| 编辑草稿 | `WKP_HEIGHT_EDIT` |
| 调整等级 | `WKP_HEIGHT_LEVEL_UPGRADE` |
| 现场检查 | `WKP_HEIGHT_CHECK` |
| 现场许可 | `WKP_SITE_PERMIT` |
| 暂停/恢复 | `WKP_SUSPEND` / `WKP_RESUME` |
| 强制终止 | `WKP_TERMINATE` |
| 验收/关闭 | `WKP_ACCEPT` / `WKP_CLOSE` |
| 规则配置 | `CFG_HEIGHT_WORK_RULE_EDIT` |

审计记录至少包含租户、票号、区域、操作人、动作、前后状态、规则版本、命中规则、原因、时间、位置和证据引用。日志禁止输出完整身份证号、手机号、签名原图和大附件内容。

## 8. 安全与降级

- 天气、定位和传感器数据只读接入，不允许反向写 OT 控制逻辑。
- 外部数据返回值必须携带来源和采集时间；过期数据按配置转人工复核或阻断。
- 天气服务不可用时不得静默放行。允许人工复核时，必须填写原因、上传证据并审计。
- 移动端可离线保存草稿、照片和监护记录；许可和恢复必须在线校验。
- 服务端校验为准，前端禁用按钮仅用于交互提示。

## 9. 测试方案

### 9.1 单元测试

| 测试类 | 覆盖 |
| --- | --- |
| `HeightWorkLevelCalculatorTest` | `2m`、`5m`、`15m`、`30m` 边界和非法高度 |
| `HeightWorkRiskClassRuleTest` | 标准危险因素、企业因素、A/B 类 |
| `HeightWorkPreCheckServiceTest` | 各检查点硬阻断、提示和人工复核 |
| `HeightWorkExpiryRuleTest` | `7 天` 有效期、到期后恢复阻断 |

### 9.2 集成测试

- 创建 → 提交 → 审批 → 许可 → 暂停 → 恢复 → 验收 → 关闭。
- B 类和四级作业强化门槛。
- 天气数据正常、过期、不可用和超限。
- SIMOPS `WARN/COORDINATE/BLOCK`。
- 人员资质过期、防护检查失败、锚点未确认。
- 非高处票调用专项接口返回明确错误。
- 重复提交、并发许可、并发恢复返回 HTTP `409`。

## 10. 上线与回滚

### 10.1 实施任务

| 批次 | 内容 |
| --- | --- |
| H1 | DDL、Entity、Mapper、专项详情、分级分类、默认措施 |
| H2 | 防护检查、环境检查、天气客户端、专项 pre-check |
| H3 | 通用接口增强、交底签字复用、流程进度、验收关闭、移动端 |
| H4 | SIMOPS 种子规则、通知、报表、联调、灰度和审计抽查 |

### 10.2 开关

```yaml
psm:
  height-work:
    enabled: ${PSM_HEIGHT_WORK_ENABLED:false}
    weather-check-enabled: ${PSM_HEIGHT_WORK_WEATHER_CHECK_ENABLED:false}
    weather-manual-review-enabled: ${PSM_HEIGHT_WORK_WEATHER_MANUAL_REVIEW_ENABLED:true}
```

### 10.3 回滚

- 功能开关关闭后，高处票回退到通用作业票流程，不删除专项数据。
- DDL 仅新增表，不做破坏性回滚。
- 已归档票保持只读；在途专项票回滚前导出清单，按企业制度完成或重新办理。

## 11. 上线检查

- 标准危险因素种子和企业规则已审批发布。
- 天气数据来源、采集时间、缓存和不可用策略完成联调。
- RBAC、区域数据权限和审计日志已验证。
- 移动端离线草稿、在线许可限制已验证。
- 四级和 B 类作业抽样演练通过。
- 归档 PDF、报表和监管映射已完成字段核对。

# 消息待办 · 共用能力与实施顺序

## 1. 共用能力

### 1.1 模板与变量

| 能力 | 说明 |
| --- | --- |
| 模板编码 | 全局唯一 `templateCode`，版本由配置中心管理 |
| 变量 | `Map<String,String>`，渲染失败阻断 send |
| 多语言 | 二期对接 `I18nUtil`，模板分 `locale` |
| 审计 | 模板发布、通道密钥变更记审计日志 |

### 1.2 幂等与去重

| 键 | 格式建议 |
| --- | --- |
| 通知 | `{bizType}:{bizId}:{event}:{userId}` |
| 外通道 | 通知 requestId + `:SMS` / `:EMAIL` |
| 定时任务 | 任务批次 ID 纳入 requestId，避免每日重复可配置 |

### 1.3 租户与用户维度

- 所有查询带 `tenantId`。
- 收件箱、待办按 `userId` 隔离；服务账号不发个人待办。

### 1.4 与配置中心

| 配置 | API |
| --- | --- |
| 通知模板 | `/api/config/notifications/templates` |
| 租户通道开关 | `/api/config/notifications/channels`（N2 新增） |
| 静默/频控 | `/api/config/notifications/policies`（N2 新增） |

### 1.5 与审计、监控

- 关键 send 记业务审计（可选异步）。
- 投递失败率、队列堆积告警。
- 与 `alarm_notification_record` 对账（报警侧已有发送记录）。

## 2. 场景接入检查表（业务开发）

业务新增通知/待办时自检：

- [ ] 是否走 `CentralNotificationClient`，未直连厂商
- [ ] 是否提供稳定 `requestId`
- [ ] 是否设置 `bizType` / `bizId` 供跳转
- [ ] 待办是否可由现有状态查询得出，而非新建待办表
- [ ] 模板是否已在配置中心登记
- [ ] 高敏字段是否脱敏

## 3. 实施顺序

| 批次 | 范围 | 依赖 | 验收要点 |
| --- | --- | --- | --- |
| **N0** | 站内信 inbox 筛选、`unread-count`、Web 消息中心页、模板对接配置服务 | 一期 notification 模块 | AC-INBOX、AC-N01~04 |
| **N1** | 统一 Todo VO、Web `/workbench/todos`、审批 `workflow_task` 聚合、动火等审批通知 | 作业票审批流 | AC-TODO、或签会签 |
| **N2** | SMS/EMAIL 适配器、异步投递、管理端通道配置、频控静默 | 厂商账号、模板报备 | AC-EXT |
| **N3** | 企微/钉钉、OA 待办、用户偏好 | 企业 IM 应用 | 集成联调 |

## 4. 与作业票专项协同

| 作业票事件 | 通知模板（建议） | 待办 taskType |
| --- | --- | --- |
| 提交 | — | `APPROVE` |
| 审批通过 | `WKP_APPROVED` | `SITE_PERMIT` |
| 退回 | `WKP_RETURNED` | —（申请人重新提交） |
| 待许可超时 | `WKP_TIMEOUT_WARN` | `SITE_PERMIT` |
| 巡检/气体异常 | `WKP_MONITOR_WARN` | `MONITOR` |

详见 `05_作业票专项` 各票种技术设计中的事件表。

## 5. 上线底线

- 外通道故障不得阻塞站内信与核心业务流程。
- 禁止在日志、界面输出完整手机号、邮箱、Token。
- 待办列表不得暴露无权限业务单据（聚合层二次校验参与人）。
- 配置变更可回滚版本，历史消息保留当时渲染内容。

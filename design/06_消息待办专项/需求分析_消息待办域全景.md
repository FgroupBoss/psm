# 需求分析 · 消息待办域全景

## 1. 背景与目标

石油化工 PSM 平台中，**通知**与**待办**是跨模块横切能力：作业票审批、现场许可、报警处置、证书到期等均依赖及时触达与可执行入口。一期已实现站内信发送与移动侧「状态聚合待办」，但 Web 待办中心、审批待办、外通道真实发送尚未统一建模。

本专项目标：

1. 厘清**通知 vs 待办**边界，避免同一业务事件重复建设两套状态。
2. 覆盖**站内信、短信、邮件**及企微/钉钉预留的完整产品与技术路径。
3. 形成可分期验收的场景矩阵与接口契约，供各业务域接入。

## 2. 域边界

```text
业务域（作业票/报警/承包商/配置…）
        │ 事件 / 状态变更
        ▼
┌───────────────────────────────────────┐
│  消息编排层（psm-notification-service） │
│  · 模板渲染 · 渠道路由 · 幂等 · 投递日志  │
└───────────────┬───────────────────────┘
                │
     ┌──────────┼──────────┐
     ▼          ▼          ▼
  站内信     短信/邮件    IM（预留）
     │
     ▼
  用户收件箱（已读/跳转）

业务域（审批实例、单据状态）
        │
        ▼
┌───────────────────────────────────────┐
│  待办聚合层（BFF / 待办查询服务）        │
│  · 只读聚合 · 不持久化业务状态副本      │
└───────────────────────────────────────┘
                │
                ▼
  Web 工作台 / 移动端待办列表 → 深链到业务页
```

| 能力 | 事实源 | 本域职责 |
| --- | --- | --- |
| 作业票是否在「待现场许可」 | `work_permit.status` | 待办聚合查询，不发 duplicate 状态表 |
| 用户是否已读某条提醒 | `notification_message.read_flag` | 消息中心维护 |
| 短信是否发送成功 | `notification_delivery_log` | 外通道适配器写回 |
| 审批节点谁未签 | `workflow_task`（规划） | 待办项指向 `taskId` |

## 3. 用户角色与诉求

| 角色 | 通知诉求 | 待办诉求 |
| --- | --- | --- |
| 申请人 | 审批结果、退回原因、超时预警 | 补充材料、重新提交 |
| 审批人 | 待审提醒、或签/会签进度 | 审批、驳回、退回 |
| 许可人/监护人 | 待许可、巡检到期、气体检测失效 | 现场许可、监护记录 |
| 值班/调度 | 报警升级、区域高风险 | 报警确认、处置、复核 |
| 承包商管理员 | 证书到期、停权 | 资质复审、人员维护 |
| 系统管理员 | 通道故障、堆积告警 | 模板/通道配置、投递对账 |

## 4. 场景矩阵

### 4.1 仅通知（提醒）

| 场景编码 | 触发 | 默认渠道 | 模板示例 |
| --- | --- | --- | --- |
| `ALARM_ESCALATION` | 报警升级 | 站内信 + 可选短信 | 一期已接入 |
| `CERT_EXPIRE_WARN` | 证书 N 天内到期 | 站内信 | 一期已接入 |
| `WKP_TIMEOUT_WARN` | 作业计划结束临近/超时 | 站内信 | 一期已接入 |
| `WKP_APPROVED` | 审批通过 | 站内信 | 二期 |
| `WKP_RETURNED` | 审批退回 | 站内信 | 二期 |
| `HAZARD_OVERDUE` | 隐患逾期 | 站内信 | 文档已列模板 |
| `HAZARD_ESCALATION` | 隐患升级 | 站内信 | 文档已列模板 |

### 4.2 通知 + 待办（需用户动作）

| 场景 | 待办类型 | 通知作用 |
| --- | --- | --- |
| 作业票待审批 | `APPROVE` | 提醒审批人打开待办 |
| 作业票待现场许可 | `SITE_PERMIT` | 提醒许可人；移动一期已聚合 |
| 作业票待验收 | `ACCEPTANCE` | 提醒负责人 |
| 报警待确认/处置 | `ALARM_HANDLE` | 移动一期 `ALARM_FEEDBACK` |
| 证书待复审 | `CERT_REVIEW` | 二期承包商 |

### 4.3 外通道增强场景（N2+）

| 场景 | 建议渠道 | 说明 |
| --- | --- | --- |
| 特级动火待审 | 短信 + 站内信 | 高优先级，需频控 |
| 报警超时未确认 | 短信 + 站内信 | 值班手机 |
| 夜间非紧急 | 仅站内信 | 尊重静默时段配置 |

## 5. 与一期现状的差异

| 项 | 一期现状 | 本专项目标 |
| --- | --- | --- |
| 站内信 | `send` / `inbox` / 已读 | 分类、批量、业务深链、未读角标 API |
| 外通道 | 枚举 + `delivery_log` 仅 IN_APP | 适配器 + 真实 SMS/EMAIL |
| 待办 | `MobileTaskService` 查作业票+报警状态 | 统一 `TodoItem` 模型 + Web + 审批 |
| 模板 | 内置 `NotificationTemplateSupport` | 对接 `psm-config-rule-service` 远程模板 |
| OA | PRD 预留 | N3 待办推送/回写 |

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 幂等 | 业务发送带 `requestId`，重复不重复落库 |
| 性能 | 收件箱分页 P95 ≤ 3s；待办聚合 P95 ≤ 2s（单用户 ≤ 200 条） |
| 安全 | 日志脱敏手机号/邮箱；通道密钥走 Jasypt |
| 可用性 | 外通道失败不阻塞站内信；支持异步重试 |
| 合规 | 短信需签名与模板报备；支持按租户关闭外通道 |
| 审计 | 配置变更、强制重发、管理员代发需审计 |

## 7. 验收原则（域级）

- 任意业务模块通过**同一 send 契约**发通知，不出现多套收件箱。
- 用户在同一入口看到**待办全集**（至少覆盖一期移动已有类型 + Web 审批）。
- 外通道发送可在 `notification_delivery_log` 对账到厂商回执。
- 通知与待办点击均可**深链**到正确业务页且带租户/权限校验。

# 产品设计 · 站内信与收件箱

## 1. 产品目标

为 Web 管理端与移动端提供统一的**消息收件箱**：查看提醒、区分已读未读、按业务跳转，支撑角标与「消息中心」导航，不承担审批操作本身（操作在业务页/待办完成）。

## 2. 页面清单

| 端 | 页面 | 功能 |
| --- | --- | --- |
| Web | 消息中心列表 | 分页、未读筛选、按业务类型/时间筛选 |
| Web | 消息详情 | 正文、关联业务、标记已读、跳转业务 |
| Web | 顶栏角标 | 未读数轮询或 WebSocket（二期可选） |
| 移动 | 通知 Tab | 与待办 Tab 分离；列表 + 详情 |
| 移动 | 角标 | 底部导航 `notifications` 未读提示（现有壳子可接 API） |

## 3. 消息卡片字段

| 字段 | 说明 | 展示 |
| --- | --- | --- |
| `title` | 标题 | 列表主标题 |
| `content` | 摘要/正文 | 列表一行摘要，详情全文 |
| `templateCode` | 模板编码 | 管理端排障可见，用户端可选隐藏 |
| `bizType` / `bizId` | 业务关联 | 决定跳转路由 |
| `readFlag` / `readAt` | 已读状态 | 未读加粗/蓝点 |
| `createdAt` | 接收时间 | 相对时间 + 绝对时间 |

### 3.1 业务跳转规则

| bizType | 跳转目标 |
| --- | --- |
| `WORK_PERMIT` | 作业票详情（带 `id`） |
| `ALARM` | 报警详情/处置页 |
| `CONTRACTOR_CERT` | 承包商人员/证书页 |
| `HAZARD` | 隐患详情（二期） |
| 空 | 仅展示详情，无跳转按钮 |

## 4. 交互规则

| 规则 | 说明 |
| --- | --- |
| 默认排序 | 未读优先，同组内 `createdAt` 降序 |
| 单条已读 | 打开详情或点击「标为已读」 |
| 全部已读 | 二次确认后批量更新 |
| 删除 | 一期不做物理删除，仅已读归档（二期可选软删） |
| 权限 | 仅能查看 `tenantId + userId` 本人消息 |

## 5. 与待办的区分（UX）

| 维度 | 站内信 | 待办 |
| --- | --- | --- |
| 文案 | 「您有一条报警升级提醒」 | 「待现场许可 · 动火票 WP-001」 |
| 主操作 | 知道了 / 查看详情 | 去处理（进入业务动作页） |
| 完成条件 | 已读即可 | 业务状态迁移（如已许可） |
| 列表入口 | 消息中心 / 通知 Tab | 工作台 / 待办 Tab |

同一业务事件可同时产生：**一条站内信** + **一条待办**（例如待审批）；产品上不合并为一条，避免用户误以为「已读即已办」。

## 6. 分类与筛选（N0+）

| 筛选项 | 值 |
| --- | --- |
| 已读状态 | 全部 / 未读 / 已读 |
| 业务类型 | 作业票、报警、承包商、系统 |
| 时间 | 今天 / 7 天 / 30 天 |

## 7. 验收标准

- AC-INBOX-01：发送后 5s 内列表可见未读消息。
- AC-INBOX-02：点击带 `bizType` 的消息进入对应业务页且权限正确。
- AC-INBOX-03：全部已读后角标为 0。
- AC-INBOX-04：同 `requestId` 不重复显示两条。

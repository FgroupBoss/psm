# 技术设计 · 消息通知服务落地

## 1. 服务定位

`psm-notification-service`（当前实现落在 `psm-identity-api` 的 `notification` 模块，迁移/独立服务按四期治理规划）作为**唯一通知编排入口**，对外提供 send / inbox / read，对内扩展多通道投递。

## 2. 架构

```text
业务服务 ──HTTP──▶ CentralNotificationClient
                        │
                        ▼
              NotificationController (/api/notifications/*)
                        │
                        ▼
              NotificationServiceImpl
                 ├─ 模板渲染（本地 / 远程配置）
                 ├─ 幂等（requestId）
                 ├─ notification_message（IN_APP）
                 └─ ChannelDispatcher
                        ├─ InAppDispatcher（同步）
                        ├─ SmsDispatcher（异步 N2）
                        └─ EmailDispatcher（异步 N2）
```

**约束**：业务模块禁止直接调用短信/邮件 SDK，仅调用 `CentralNotificationClient` 或等价 Feign。

## 3. 数据表（延续一期并扩展）

### 3.1 `notification_message`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint PK | |
| tenant_id | bigint | 租户 |
| user_id | bigint | 收件人 |
| request_id | varchar(64) | 幂等键，建议 `{bizType}:{bizId}:{event}:{userId}` |
| channel | varchar(16) | 主展示渠道，站内信固定 `IN_APP` |
| template_code | varchar(64) | 模板编码 |
| title / content | varchar/text | 渲染结果 |
| biz_type / biz_id | varchar/bigint | 业务关联 |
| read_flag | tinyint | 0 未读 1 已读 |
| read_at | datetime | |
| created_at | datetime | |

索引：`(tenant_id, user_id, read_flag, created_at)`。

### 3.2 `notification_delivery_log`

| 列 | 说明 |
| --- | --- |
| message_id | 关联站内信（外通道独立发送时可空） |
| channel | `IN_APP` / `SMS` / `EMAIL` / … |
| status | `SENT` / `FAILED` / `SKIPPED` / `PENDING` |
| provider_msg_id | 厂商回执 ID |
| error_code / error_msg | 失败原因 |
| sent_at | |

一期实现：站内信发送写一条 `IN_APP` + `SENT`。

### 3.3 规划表（N2）

| 表 | 说明 |
| --- | --- |
| `notification_template` | 若未完全走 config-service，可本地缓存副本 |

## 4. 核心接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/notifications/health` | GET | 健康与计数 |
| `/api/notifications/send` | POST | 发送（幂等 `requestId`） |
| `/api/notifications/inbox` | GET | 分页；`read`、`bizType`、时间范围 |
| `/api/notifications/unread-count` | GET | 角标（N0 新增） |
| `/api/notifications/{id}` | GET | 详情 |
| `/api/notifications/{id}/read` | POST | 单条已读 |
| `/api/notifications/read-all` | POST | 全部已读 |

### 4.1 Send 请求体（扩展）

```json
{
  "tenantId": 1,
  "userId": 100,
  "requestId": "WORK_PERMIT:88:TIMEOUT:100",
  "templateCode": "WKP_TIMEOUT_WARN",
  "variables": { "permitNo": "WP-001", "hours": "2" },
  "title": null,
  "content": null,
  "bizType": "WORK_PERMIT",
  "bizId": 88,
  "channels": ["IN_APP", "SMS"]
}
```

校验失败抛业务异常（与 `GlobalExceptionHandler` 一致）；模板/变量缺失返回可解释错误（AC-N03）。

### 4.2 模板来源

| 阶段 | 实现 |
| --- | --- |
| 当前 | `NotificationTemplateSupport` 内置 Map |
| N0 | 启动加载 + 对接 `/api/config/notifications/templates` |
| 变更 | 配置发布版本号写入 message 扩展字段（可选 `config_version`） |

## 5. 通道枚举

与代码 `NotificationChannel` 一致：

- `IN_APP`、`SMS`、`EMAIL`、`WECHAT`、`DINGTALK`

## 6. 投递流程（N2 短信/邮件）

```text
send()
  → 事务内写 message + IN_APP log
  → 发布 NotificationDeliveryEvent（MQ 或 @Async）
  → SmsDispatcher
       → 厂商 API
       → 更新 delivery_log（SENT/FAILED）
       → 失败重试（指数退避，最多 3 次）
```

- 外通道失败**不回滚**站内信。
- 重试幂等以 `requestId + channel` 为键。

## 8. 安全与观测

- `inbox` / `read` 必须校验 `tenantId + userId` 与登录上下文一致。
- `send` 仅允许**服务间**调用（网关白名单 / 内部 Token），禁止浏览器直连。
- 指标：`notification_send_total`、`delivery_failed_total`、通道延迟直方图。
- 日志：`templateCode`、`messageId`、`tenantId`、`userId`；禁止打印 `variables` 中手机号全文。

## 9. 验收（技术）

- AC-N01 ~ AC-N04：与一期落地设计一致。
- AC-N05：`channels` 含 SMS 时异步投递且 log 可追溯。
- AC-N06：`unread-count` 与 inbox 未读数一致。

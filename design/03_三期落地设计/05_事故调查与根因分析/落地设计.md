# 事故调查与根因分析落地设计

## 1. 模块目标

建立事故、未遂事件和高潜在事件的调查闭环，支持证据收集、时间线复盘、根因分析、纠正预防措施（CAPA）和经验反馈，推动风险库、培训和规则持续改进。

## 2. 功能范围

| 子模块 | 三期范围 |
| --- | --- |
| 事件报告 | 事故、未遂、高潜在事件报告和分级 |
| 调查立项 | 调查组、范围、计划、权限 |
| 证据管理 | 时间线、附件、照片、视频、访谈记录 |
| 根因分析 | 直接原因、间接原因、管理原因、屏障失效 |
| CAPA | 纠正措施、预防措施、责任人、期限、验证 |
| 经验反馈 | 风险库更新、培训需求、制度修订、规则优化建议 |

## 3. 关键流程

```text
事件报告
 -> 分级和调查立项
 -> 收集证据和访谈
 -> 建立事件时间线
 -> 分析直接原因和根本原因
 -> 制定 CAPA
 -> 整改验证和关闭
 -> 经验反馈和复盘归档
```

## 4. 状态机

### 4.1 事件调查状态

```text
已报告 -> 待立项 -> 调查中 -> 待评审 -> CAPA执行中 -> 已关闭
待立项/调查中 -> 已取消
```

### 4.2 CAPA 状态

```text
待分派 -> 执行中 -> 待验证 -> 已关闭
待验证 -> 已退回
任意非关闭 -> 已逾期（并行标记）
```

## 5. 数据设计

| 表 | 说明 |
| --- | --- |
| `incident_report` | 事件报告 |
| `incident_investigation` | 调查主表 |
| `incident_timeline` | 时间线 |
| `incident_evidence` | 证据附件 |
| `incident_interview` | 访谈记录 |
| `incident_root_cause` | 根因 |
| `incident_capa` | CAPA |
| `lesson_learned` | 经验反馈 |

## 6. 关键字段

### 6.1 事件 `incident_report`

| 字段 | 说明 |
| --- | --- |
| incident_no | 事件编号 |
| incident_type | 事故、未遂、高潜在、环境、职业健康 |
| incident_level | 一般、较大、重大 |
| occurred_at | 发生时间 |
| area_id | 发生区域 |
| equipment_id | 关联设备 |
| source_type | 人工、报警、隐患、作业、巡检 |
| source_biz_id | 来源业务 ID |
| status | 事件状态 |

### 6.2 CAPA `incident_capa`

| 字段 | 说明 |
| --- | --- |
| capa_no | CAPA 编号 |
| incident_id | 事件 ID |
| capa_type | 纠正措施、预防措施 |
| owner_user_id | 责任人 |
| due_at | 截止时间 |
| verification_user_id | 验证人 |
| evidence_file_id | 证据附件 |
| status | CAPA 状态 |

## 7. 联动规则

| 场景 | 规则 |
| --- | --- |
| 报警/隐患 | 高潜在事件可从报警、隐患一键转调查 |
| 作业票 | 作业异常或强制终止可转事件报告 |
| 屏障管理 | 根因涉及屏障失效时更新屏障健康度和降级记录 |
| 双重预防 | 经验反馈可生成风险事件或管控措施更新建议 |
| 培训 | 人因或制度类根因可生成培训需求 |

## 8. 接口设计

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/incidents` | GET/POST | 事件查询和报告 |
| `/incidents/{id}/start-investigation` | POST | 调查立项 |
| `/incidents/{id}/timeline` | GET/POST | 时间线维护 |
| `/incidents/{id}/evidence` | GET/POST | 证据维护 |
| `/incidents/{id}/root-causes` | GET/POST | 根因维护 |
| `/incidents/{id}/capa` | GET/POST | CAPA 维护 |
| `/incidents/capa/{id}/verify` | POST | CAPA 验证 |
| `/incidents/{id}/lessons-learned` | POST | 经验反馈 |

## 9. 页面设计

| 页面 | 关键能力 |
| --- | --- |
| 事件台账 | 类型、等级、状态、区域、来源筛选 |
| 调查工作台 | 调查组、时间线、证据、访谈 |
| 根因分析 | 原因分类、屏障失效、管理原因 |
| CAPA 台账 | 责任人、期限、状态、逾期、验证 |
| 经验反馈 | 风险库、培训、制度、规则更新建议 |

## 10. 验收标准

- 事件可从人工、报警、隐患、作业异常来源创建。
- 调查可维护时间线、证据、访谈和根因。
- CAPA 可分派、整改、验证、关闭并逾期升级。
- 经验反馈可生成风险库、培训或规则更新建议。
- 事故调查资料按权限控制并可审计追溯。

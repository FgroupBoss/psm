# MOC 变更管理落地设计

## 1. 模块目标

建立 Management of Change（MOC）闭环，确保工艺、设备、仪表、控制逻辑、组织人员、制度文件等变更在实施前完成风险评估、审批、培训、文件更新和投用验证。

## 2. 功能范围

| 子模块 | 三期范围 |
| --- | --- |
| 变更申请 | 变更类型、范围、原因、紧急程度、关联装置/设备 |
| 分类分级 | 工艺、设备、仪表、控制、组织、制度、临时/永久变更 |
| 影响分析 | 安全、环保、工艺、设备、仪表、电气、应急、培训、文件 |
| 审批流 | 按变更等级、专业、区域动态路由 |
| 实施管理 | 实施任务、责任人、计划时间、现场验证 |
| 关闭条件 | PHA、PSSR、培训、文件、SOP、图纸、应急预案更新 |
| 审计归档 | 版本快照、审批记录、附件、关闭报告 |

## 3. 关键流程

### 3.1 标准变更

```text
提交变更申请
 -> 初审和分类分级
 -> 专业影响分析
 -> 风险评审和审批
 -> 实施任务分派
 -> 现场实施和验证
 -> 完成关闭条件
 -> 关闭归档
```

### 3.2 紧急变更

```text
提交紧急变更
 -> 快速审批和临时控制措施
 -> 实施
 -> 限期补充完整影响分析
 -> 转标准变更关闭
```

## 4. 状态机

```text
草稿 -> 已提交 -> 初审中 -> 影响分析中 -> 审批中 -> 待实施 -> 实施中 -> 待验证 -> 已关闭
已提交/初审中/影响分析中/审批中 -> 已退回
待实施/实施中 -> 已取消
紧急变更 -> 临时生效 -> 补审中 -> 已关闭
```

## 5. 数据设计

| 表 | 说明 |
| --- | --- |
| `moc_change` | 变更主表 |
| `moc_impact_analysis` | 影响分析 |
| `moc_approval_record` | 审批记录 |
| `moc_implementation_task` | 实施任务 |
| `moc_close_condition` | 关闭条件 |
| `moc_document_update` | 文件更新 |
| `moc_training_requirement` | 培训需求 |

## 6. 关键字段

### 6.1 变更 `moc_change`

| 字段 | 说明 |
| --- | --- |
| change_no | 变更编号 |
| change_title | 变更标题 |
| change_type | 工艺、设备、仪表、控制、组织、制度 |
| change_level | 一般、较大、重大 |
| temporary_flag | 是否临时变更 |
| emergency_flag | 是否紧急变更 |
| affected_area_id | 影响区域 |
| affected_equipment_id | 影响设备 |
| risk_level | 评估后风险等级 |
| status | 变更状态 |

### 6.2 关闭条件 `moc_close_condition`

| 字段 | 说明 |
| --- | --- |
| change_id | 变更 ID |
| condition_type | PHA、PSSR、培训、文件、SOP、图纸 |
| required_flag | 是否必做 |
| owner_user_id | 责任人 |
| due_at | 截止时间 |
| completed_at | 完成时间 |
| evidence_file_id | 证据附件 |

## 7. 联动规则

| 场景 | 规则 |
| --- | --- |
| PHA/LOPA | 重大或高风险变更必须触发 PHA 复审 |
| PSSR | 涉及开停车、关键设备、工艺条件变化时触发 PSSR |
| 作业票 | 变更实施期间可生成检维修作业或限制区域高风险作业 |
| 屏障管理 | 变更影响安全屏障时生成屏障复核任务 |
| 培训 | SOP 或岗位职责变化时生成培训需求 |

## 8. 接口设计

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/moc/changes` | GET/POST | 变更查询和申请 |
| `/moc/changes/{id}/submit` | POST | 提交变更 |
| `/moc/changes/{id}/impact-analysis` | GET/POST | 影响分析 |
| `/moc/changes/{id}/approve` | POST | 审批 |
| `/moc/changes/{id}/implementation-tasks` | GET/POST | 实施任务 |
| `/moc/changes/{id}/verify` | POST | 验证 |
| `/moc/changes/{id}/close` | POST | 关闭 |

## 9. 页面设计

| 页面 | 关键能力 |
| --- | --- |
| 变更台账 | 类型、等级、状态、区域、逾期筛选 |
| 变更详情 | 申请、影响分析、审批、任务、关闭条件 |
| 影响分析表 | 多专业评估、风险等级、触发项 |
| 实施任务 | 任务分派、证据上传、进度跟踪 |
| 关闭审查 | 关闭条件检查、验证意见、归档 |

## 10. 验收标准

- 变更可完成申请、影响分析、审批、实施、验证、关闭全流程。
- 高风险变更可触发 PHA/PSSR/培训/文件更新任务。
- 紧急变更可临时生效并限期补审。
- 关闭前必须完成必做关闭条件。
- 全链路审批、任务、附件和版本可审计追溯。

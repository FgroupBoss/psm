# 三期迭代与批次任务设计

> **用途**：作为三期研发排期、批次签收、接口联调和验收追踪的统一设计基线。  
> **范围**：只做设计输出，不包含代码实现。  
> **状态口径**：以 [项目进展总览.md](./项目进展总览.md) 为唯一状态看板；本文维护任务拆分、接口契约和验收口径。

## 1. 三期目标

在一、二期风险管控闭环基础上，补齐完整 PSM 能力和集团治理能力，支撑试点基地从“在线管控”升级为“体系化风险治理”。

## 3. 全局接口约定

三期沿用一、二期接口约定，新增以下约束：

| 项 | 约定 |
| --- | --- |
| 版本化 | HAZOP 节点、MOC 影响分析、PSSR 清单、集团模板必须支持版本快照。 |
| 建议项/CAPA | 建议项、整改项、CAPA 统一采用责任人、期限、验证人、状态机、附件和审计字段。 |
| 风险引用 | 所有模块引用区域、设备、危险源、风险单元、作业票、报警时只保存业务 ID 和类型，不复制主数据。 |
| 计算结果 | LOPA、屏障健康度、集团指标的计算结果必须保留输入摘要、算法版本和计算时间。 |
| 敏感信息 | 事故调查附件和个人责任信息按权限分级，默认不进入普通统计明细。 |

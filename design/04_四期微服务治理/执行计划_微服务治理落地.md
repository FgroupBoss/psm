# 微服务治理落地执行计划

> **文档定位**：可落地的执行计划，每个步骤包含前置条件、执行动作、边界定义、验收标准、回滚方案和预估工时。
> **配套文档**：[微服务治理重构方案](./微服务治理重构方案.md)（战略设计，本文档执行依据）
> **当前基线**：2026-05-31，25 个独立服务，12 个 shared/*-api 骨架模块已创建，未填充

---

## 0. 执行总览

### 0.1 治理目标

| 维度 | 当前状态 | 目标状态 |
|---|---|---|
| 服务数量 | 25 个独立 Spring Boot 服务 | 9 个业务域服务 + 2 个独立保留 |
| 公共模块 | `psm-common-core` 职责偏宽 | 6 个职责清晰的 `common-*` 模块 |
| API 契约 | 跨服务 DTO 复制（18+ 文件） | 7 个业务域 `*-api` 模块统一契约 |
| 重复代码 | `GlobalExceptionHandler` 24 份 | 统一由 `common-web` 承载 |
| 数据库 | 每服务独立库，部分直连他服务表 | 第一阶段只合并进程，不合库 |

### 0.2 九个目标业务域

```
接入与体验层    → psm-gateway (保留) + psm-mobile-bff (保留但瘦身)
身份与组织域    → psm-identity-service          ← auth + iam
平台支撑域      → psm-platform-support-service  ← master-data + config-rule (+ file/notification/audit 可选物理合并)
实时感知域      → psm-realtime-perception-service ← alarm + location + video
作业与承包商域  → psm-operation-control-service ← work-permit + contractor
风险防控域      → psm-risk-control-service      ← dual-prevention + major-hazard + inspection
流程安全域      → psm-process-safety-service    ← moc + pha + pssr + barrier
事件治理域      → psm-incident-governance-service ← incident + governance + report
外部集成域      → psm-integration-service (保留)
```

### 0.3 执行阶段总览

```
阶段零：基线与规则冻结 ──────── 1 天
阶段一：公共模块落地 ────────── 3 天

    // 3. 验证未知异常响应结构（日志不重复打印）
}
```

**边界定义**：
- 范围内：`GlobalExceptionHandler` 统一实现 + 兼容测试
- 范围外：不迁移 `SwaggerConfig`（各服务 OpenAPI 分组名称不同，保留服务本地配置）；不修改 `ResponseVO` 结构

**验收标准**：
- [ ] `mvn -pl shared/psm-common-web -am -DskipTests=false test` 通过
- [ ] 异常处理 JSON 输出结构与现有服务一致（字段名、错误码格式）

- [ ] `BusinessException`、参数校验异常、未知异常三种场景均已覆盖测试

**回滚方案**：删除 `common-web` 中 `GlobalExceptionHandler.java`，恢复为空骨架；回退测试类

   - **不在此模块配置 DataSource**（每个服务独立配数据源）

**边界定义**：
- 范围内：Entity 基类定义、自动填充处理器
- 范围外：不配 DataSource、不配 MapperScanner、不引入具体的 Mapper/SqlSession 配置

**验收标准**：
- [ ] `mvn -pl shared/psm-common-data -am -DskipTests=false test` 通过
- [ ] 基类不包含 MyBatis-Plus 的 `@TableName`/`@TableId` 注解
- [ ] 基类不包含 `@Data` 等 Lombok 类级别注解（允许字段级别 `@TableField`）

**回滚方案**：清空 `common-data`，恢复为骨架

### 步骤 2.4：身份域、风险域、流程安全域、事件治理域 API 抽取

**前置条件**：步骤 2.1～2.3 完成

**执行动作**：

四个域的 API 模块使用统一模板，不再逐域展开：

```
psm-identity-api/          → 用户上下文 DTO、权限校验 DTO、身份查询 Client
psm-risk-api/              → 风险点摘要、重大危险源摘要、巡检摘要、风险域 Client
psm-process-safety-api/    → MOC/PHA/PSSR/Barrier 各自的对外查询 DTO 和 Client
psm-incident-governance-api/ → 事故摘要、CAPA 摘要、治理指标 DTO、报表 DTO
```

**统一规则**：
- 每个 API 模块只放：DTO、VO、枚举、Request/Response 对象、Client interface
- 不放：Entity、Mapper、ServiceImpl、Controller、配置类
- Client interface 使用 `@FeignClient` 注解，不写实现

**边界定义**：
- 范围内：为四个域各创建一批 DTO 和 Client 接口（基于现有跨服务调用梳理）
- 范围外：不迁移尚未形成跨服务调用的内部类

**验收标准**：
- [ ] 四个 API 模块 `mvn -pl shared/psm-*-api -am -DskipTests=false test` 通过

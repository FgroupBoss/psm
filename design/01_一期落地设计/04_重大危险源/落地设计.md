# 重大危险源落地设计

## 1. 模块目标

建立重大危险源“一源一档”，将危险源、区域、装置、设备、监测点位、责任人、报警、作业票和附件统一关联，为报警处置和作业许可提供风险上下文。

## 2. 功能范围

| 子模块 | 一期范围 |
| --- | --- |
| 危险源档案 | 编码、名称、类型、等级、介质、容量、区域、责任人 |
| 包保责任 | 主要负责人、技术负责人、操作负责人 |
| 点位绑定 | 监测点位、设备、安全设施绑定 |
| 附件管理 | 评估报告、备案材料、SDS、平面图、预案 |
| 关联视图 | 报警、作业票、点位趋势、责任人 |
| 状态管理 | 正常、停用、检修、异常 |

## 3. 业务流程

```text
新建危险源档案
 -> 维护分级和介质信息
 -> 绑定区域、装置、设备
 -> 配置包保责任人
 -> 绑定监测点位和安全设施
 -> 上传附件和预案
 -> 审核发布
 -> 报警和作业持续关联
```

## 4. 关键规则

- 危险源必须绑定区域、等级和责任人。
- 关键点位必须维护来源系统、原始点号、单位和阈值。
- 点位离线超过配置阈值时生成报警或待办。
- 危险源区域存在未关闭高等级报警时，影响作业许可。
- 危险源停用后不得继续作为新作业的风险对象。

## 5. 页面设计

| 页面 | 关键能力 |
| --- | --- |
| 危险源台账 | 查询、分级筛选、新增、导入、导出 |
| 危险源详情 | 档案、责任人、点位、报警、作业、附件 |
| 点位趋势 | 当前值、历史趋势、阈值、在线状态 |
| 附件资料 | 上传、分类、版本、下载 |
| 风险视图 | 按区域展示危险源等级和报警状态 |

## 6. 接口设计

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/major-hazards` | GET/POST | 危险源查询和新增 |
| `/major-hazards/{id}` | GET/PUT | 危险源详情和修改 |
| `/major-hazards/{id}/points` | GET/POST | 点位绑定 |
| `/major-hazards/{id}/attachments` | GET/POST | 附件维护 |
| `/major-hazards/{id}/alarms` | GET | 关联报警 |
| `/major-hazards/{id}/permits` | GET | 关联作业票 |
| `/major-hazards/risk-context` | POST | 作业许可风险上下文查询 |

## 7. 数据设计

| 表 | 说明 |
| --- | --- |
| `major_hazard` | 危险源主表 |
| `major_hazard_responsibility` | 包保责任 |
| `major_hazard_point_rel` | 危险源点位关联 |
| `major_hazard_attachment` | 档案附件 |
| `major_hazard_status_log` | 状态变更记录 |

## 8. 与其他模块关系

| 模块 | 关系 |
| --- | --- |
| 基础主数据 | 危险源绑定区域、装置、设备、点位 |
| 报警中心 | 报警根据点位映射到危险源 |
| 作业票 | 作业票按区域和设备关联危险源 |
| 报表大屏 | 提供危险源数量、等级、在线率、报警状态 |

## 9. 验收标准

- 可按危险源查看档案、责任人、点位、报警、作业和附件。
- 点位数据可展示当前值、状态和趋势。
- 危险源区域高等级报警可被作业许可规则识别。
- 关键字段和状态变更有审计记录。
